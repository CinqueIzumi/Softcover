# R8 and keep rules

R8 shrinks the release build by removing code nothing reaches, optimises what is left, and renames classes,
methods and fields to short names. It decides what is reachable by reading static references in the code. A
class that is only reached by name, from a manifest entry, a class-name string, a library that reads a class
name from meta-data, or reflection, has no static reference, so R8 can remove or rename it and the build
crashes in release only. Debug builds do not run R8, so none of this shows up until a minified build is tested.

## How it's enabled

- `app/build.gradle.kts`: `release { optimization { enable = true … } }`. `keepRules.files` adds
  `app/src/main/keepRules/app.keep`; the rest come from libraries and modules as consumer rules.
- The `minified` build type is `initWith(release)`, debug-signed, with `matchingFallbacks += "release"`. The
  `:smoketest` device suite installs it. It shares the release `applicationId`, so it replaces an installed
  release build. `src/release` holds the no-op debug-routes binding that `src/main` references; the `minified`
  source set adds it explicitly.
- `app.keep` keeps `SourceFile` and `LineNumberTable` and renames the source file to `SourceFile`, so crash
  reports keep line numbers.

## Keep-rule ownership

The module that owns a class reached by name owns its keep rule. Rules sit in
`src/<sourceSet>/keepRules/*.keep` and reach R8 as consumer rules. `:app` has none beyond the line tables.

- `feature/widget/src/androidMain/keepRules/widget.keep`
  - Keeps the no-arg constructor of every Glance `ActionCallback`. Glance instantiates them by class name and
    its own rule keeps the class but not the constructor, so a widget tap fails with an
    `InstantiationException`.
  - Keeps the names of `GlanceAppWidget` subclasses. Glance stores the provider's canonical name and the app
    looks widgets up by `javaClass`, so a rename makes placed widgets undetectable after an upgrade.
- `core/presentation/src/androidMain/keepRules/navigation.keep`
  - Keeps the names of Voyager `Screen` subclasses. `Screen.key` defaults to the class name and keys saved
    state and ScreenModels, so renamed or merged screens could collide.
  - Keeps the non-transient fields of `Screen` subclasses. Android saves the back stack through Java
    serialization and R8 would drop fields it sees as never read; see `@TransientNavArg`.
- `feature/scan/src/androidMain/keepRules/scan.keep`
  - Keeps the no-arg constructor of every ML Kit `ComponentRegistrar`. ML Kit reads registrar names from
    manifest meta-data and instantiates them reflectively. Its shipped rule keys on `@UsedBy`, which the
    registrars lack, so without this the barcode scanner never initialises.

Scope a rule to the type and member that is reached. Never use `-dontobfuscate`, `-keep class **` or a wildcard
over a package; they hide the next breakage instead of fixing it.

## The gates

### `:app:checkR8KeepContract`

Applied by the `softcover.android.r8-keep-contract` plugin. It registers `checkR8KeepContractRelease`,
`checkR8KeepContractMinified` and an aggregate that depends on both. It is not part of `check`; CI calls it
(see CI). It reads each variant's `mapping.txt`, `seeds.txt`, `configuration.txt`, merged manifest and compiled
classes, and fails when:

- a class named in the manifest (`application`, `activity`, `service`, `receiver`, `provider`), the
  `appComponentFactory`, an `androidx.startup` initializer, a Firebase `ComponentRegistrar` meta-data entry or
  the Room `SoftcoverDatabase_Impl` is missing from `mapping.txt` or renamed;
- a concrete project `Screen` (Voyager) or `GlanceAppWidget` is renamed;
- a project `ActionCallback` or `ComponentRegistrar` with a no-arg constructor, a project `ListenableWorker`
  with a `(Context, WorkerParameters)` constructor, the `appComponentFactory`, a registrar from meta-data or a
  startup initializer has no kept `<init>` in `seeds.txt`;
- a rule in any `src/*/keepRules/*.keep` file (`smoketest/` excluded, its rules apply to the test APK) is
  absent from R8's `configuration.txt`, which catches a keep file that never reaches the build.

Read the result in `app/build/reports/r8-keep-contract/<variant>.txt`: one line per violation, naming the class
and why, or `R8 keep contract holds`. The Gradle failure message lists the same lines.

### Detekt: `softcover:NoReflection` and `softcover:ScreenConstructorProperty`

They run on the type-resolved tasks `styleCheck` fans out to: `detektAndroidMain`, `detektJvmMain` and `detektMain`
(`:app`'s variants, `:desktopApp`, `:smoketest`). The plain `detekt` task is disabled. Only
`ScreenConstructorProperty` is `@RequiresTypeResolution` and does nothing without a binding context;
`NoReflection` uses one when present and otherwise falls back to matching the call name.

- `NoReflection` reports `forName`, `loadClass`, `getDeclaredMethod`, `getMethod`, `getDeclaredField`,
  `getField`, `getDeclaredConstructor` and `getConstructor` on `java.lang.Class` and `ClassLoader`, and any
  import from `kotlin.reflect.full` or `kotlin.reflect.jvm`. Reach the class through a static reference.
- `ScreenConstructorProperty` reports a Voyager `Screen` constructor property that Android's Java
  serialization of the back stack cannot save. Allowed: primitives, unsigned types, primitive arrays, strings,
  enums, and project types that are `java.io.Serializable`. Anything else, such as a domain model, takes
  `@TransientNavArg` (`core/presentation/.../navigation/TransientNavArg.kt`). On Android it is
  `kotlin.jvm.Transient`: the value restores as `null` and the screen re-fetches by id.
- Both exclude `**/smoketest/**`, `src/debug` and the test source sets (`config/detekt/softcover-rules.yml`).

### The `:smoketest` device suite

A self-instrumenting `com.android.test` module. The test APK runs in its own process and drives the installed
minified app, so the runner is never loaded into R8-stripped code. `MinifiedContractTest` probes the app's
classes by original name through a `PathClassLoader`; `SignedInJourneyTest` is a read-only UI Automator
journey on a signed-in account.

```bash
scripts/gradle-quiet.sh :smoketest:pixelApi36MinifiedAndroidTest
```

- The token comes from the `HARDCOVER_SMOKE_TOKEN` environment variable, else `hardcover.apiToken` in
  `local.properties`. It reaches the test only as the `hardcoverToken` instrumentation argument. Never log,
  print or commit it, and never put it in a resource or `BuildConfig`.
- **Re-runs.** A second local run with unchanged inputs is `UP-TO-DATE` and tests nothing. Add `--rerun`.
- The journey finds nodes by `By.res`. `MainActivity` sets `testTagsAsResourceId`, so a Compose `testTag` is
  a resource id. Tags live in per-feature `*TestTags` objects (`LibraryTestTags`, `BookDetailTestTags`); add
  new ones there, not as string literals.

## CI

- `.github/workflows/r8-smoke.yml` is a reusable workflow, job name `R8 release smoke`. `ci-full.yml` calls it
  on PRs into `main` and on pushes; `release.yml` calls it as `smoke`.
- It runs `:app:checkR8KeepContract` and `:smoketest:pixelApi36MinifiedAndroidTest` on a managed emulator.
- The first step fails fast when `HARDCOVER_SMOKE_TOKEN` is empty, which is the case for fork and Dependabot
  PRs. A scan for the token runs before any report upload, and the upload is skipped if it finds one.
- `release.yml` runs `checkR8KeepContractRelease` in the same step as `assembleRelease` and `bundleRelease`.
  `mapping.txt` is staged as `Softcover-<tag>-mapping.txt`, passed to Play as `mappingFile`, and attached to
  the GitHub release. The `play` and `release` jobs need `smoke`.
- The required check name for the `main` ruleset is `r8-smoke / R8 release smoke`. Add it to the ruleset after
  the first run, once GitHub knows the name.

## Checklists

### Implementer

When you add any of these, do the matching step:

- A **manifest component**: the keep contract covers it. Run `:app:checkR8KeepContract`.
- A **WorkManager worker**: keep the `(Context, WorkerParameters)` constructor. The contract fails if
  `seeds.txt` lacks it.
- A **Glance widget or `ActionCallback`**: `widget.keep` covers both kinds; confirm the new class matches.
- A **library that loads classes by name** (ML Kit, a startup `Initializer`): find the class it instantiates,
  confirm the library's own rule keeps the constructor, and add a narrow rule in the owning module if not.
- A **`Screen` argument**: serializable, or `@TransientNavArg`.
- **Anything persisted or looked up by class name** (a Glance provider stored in DataStore, a `Screen` in the
  saved back stack): add a `-keepnames` rule in the owning module, as `widget.keep` and `navigation.keep` do.
- **Any reflection**: don't. Use a static reference; `NoReflection` blocks it.

A new rule goes in the owning module's `src/<sourceSet>/keepRules/<name>.keep` with a comment saying what
reaches the class and what breaks without it. Then run `:app:checkR8KeepContract` and the device suite.

### Reviewer

- A new manifest entry, worker, widget, startup initializer or `Screen` argument has the keep rule or
  annotation it needs; do not rely on the contract alone.
- A new keep rule is narrow, lives in the owning module, and explains itself. Flag `-dontobfuscate`,
  `-keep class **`, a package wildcard, or a rule in `:app` for another module's class.
- No `@Suppress` or baseline entry for either detekt rule, and no widened `smoketest` exclusion.
- A change to `r8-smoke.yml` or the R8 parts of `release.yml` keeps the secret check, the token scan before
  upload, and `needs: smoke` on `play` and `release`.
- A screen the journey should reach has its tags in a `*TestTags` object.

## Debugging a release-only crash

1. Reproduce on the `minified` build: `scripts/gradle-quiet.sh :app:installMinified`. It shares the release
   `applicationId` but is debug-signed, so uninstall a Play-installed build first: Android refuses an
   update signed with a different key.
2. R8's outputs are in `app/build/outputs/mapping/<variant>/`. `release` and `minified` both
   hold `mapping.txt`, `seeds.txt`, `configuration.txt`, `usage.txt`, `resources.txt`, `mapping.prt` and the
   `configanalyzer` reports. `seeds.txt` lists what was kept and `usage.txt` what was removed.
3. Retrace a stack trace with the mapping of the same build:
   `retrace app/build/outputs/mapping/release/mapping.txt trace.txt`. `retrace` ships in the Android
   command-line tools (`cmdline-tools/latest/bin`; install them from the SDK Manager if that folder is missing). Play Console retraces on its own once the release's
   `mapping.txt` is uploaded.
4. A `ClassNotFoundException`, `NoSuchMethodException` or `InstantiationException` points at a class reached by
   name. Look it up in `usage.txt` (removed) or `mapping.txt` (renamed), add a narrow rule to the owning
   module, and extend the contract if the class kind is new.
