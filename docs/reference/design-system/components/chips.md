# Components — Chips

### Expandable flow row

`ExpandableFlowRow` is the canonical wrapping chip/tag container for a set that can grow unbounded. It wraps items across lines and, past `collapsedLines`, collapses to that many lines behind a trailing **"show more"** affordance, so a long set never buries the content beneath it. **How much a tap reveals is the call site's choice**, via `expansion`: `FlowRowExpansion.Progressive(linesPerExpand)` is the default *gradual*, line-based reveal (built on `FlowRow`'s `maxLines` + `FlowRowOverflow.expandIndicator`), while `FlowRowExpansion.Full` opens the entire set in one tap — reach for `Full` when the set is something the user asked to *browse*, where drip-feeding lines makes the full contents effectively unreachable. `collapsible = true` adds a matching **"show less"** back to `collapsedLines` (switching the layout to `FlowRowOverflow.expandOrCollapseIndicator`); it is off by default, but a `Full` reveal over an **unbounded** set must set it, or one tap displaces everything below the row for the surface's whole lifetime. Both bounds are caller-set; each affordance defaults to an editorial `surfaceContainerHigh` / `primary` pill matching `Chip`'s anatomy but can be replaced via `showMoreIndicator` / `showLessIndicator`. Its `content` is a plain slot (no `FlowRowScope` receiver) so a call site needs no experimental opt-in. The library filter's facet chips use it on the desktop panel form (§3.5) — where a fixed-width panel can't scroll a chip row sideways — while the narrow bottom sheet keeps each facet on one horizontally scrolling line; the tag editor's suggestion cloud uses `Progressive(linesPerExpand = 3)` + `collapsible`, since a gradual per-tap reveal reads better than dumping the user's whole (potentially 40-60+ tag) vocabulary at once. Reach for it for any wrapping chip set that can run long; do not hand-roll a `FlowRow` with manual slice-and-count state. It is the foundation `designsystem-core` layout primitive (`nl.rhaydus.designsystem.layout.ExpandableFlowRow`); the default "show more" pill is the foundation's (label set via `showMoreLabel`), and the library filter call site uses it with all defaults.

### Pill chip

`Chip(model: ChipUiModel, onEvent)` (`core:component`, `chip/`) is the canonical fully-rounded (`RoundedCornerShape(percent = 50)`) chip: a `Surface` carrying a single `labelMedium` label. It backs both the library filter facets and the book-detail tag chips, so the chip anatomy lives in one place — reach for it instead of hand-rolling a `Surface`-and-`Text` pill. Selected → `secondaryContainer` / `onSecondaryContainer` (label semibold); idle → `surfaceContainerHigh` / `onSurface` (label medium) — the authoritative idle colour for the pill-chip anatomy. `ChipUiModel.clickable` picks the mode: `true` for an interactive chip (toggles, filters), which reports `ChipEvent.Clicked(key)`; `false` for a **read-only** chip — the surface then carries no ripple and no click role, the mode used for the book-detail tag chips. The tap carries the model's `key` rather than a per-item lambda (§7 R1), so a chip row in a lazy list stays skippable; the caller recovers its own payload from a lookup map beside the models in state. A `concealed` flag renders the chip as a **spoiler redaction** (§2.1 spoiler register): the label is drawn `Color.Transparent` so it still reserves its width but cannot be read, beneath a solid `spoilerCover` fill — the same treatment `RichText` gives an inline spoiler run. Because the hidden label still measures at full width, revealing it (re-render with `concealed = false`) does not reflow the row. Used for book-detail content-warning chips.
