# Components — Covers

### Rhaydus shimmer image

The canonical loader for non-cover images (avatars, author photos, any free-aspect imagery). Provided by the foundation **`designsystem-image`** module (`nl.rhaydus.designsystem.image.RhaydusShimmerImage`). Use it rather than reaching for a raw image library; it shares the project's Coil loader, shimmer placeholder (suppressed under reduced motion), and `SkeletonCrossfade` behavior. Signature: `(model: Any?, contentDescription: String?, modifier, contentScale, isLoading)`. `Cover` is for book covers only — everything else uses `RhaydusShimmerImage`.

### Cover

`Cover(model: CoverUiModel)` (`core:component`, `cover/`) is the canonical book cover and the only way the app draws one. Always 2:3 aspect, subtle radius, optional soft shadow. The model carries an **already-resolved** `CoverSource` — `Local(path, cacheKey)` or `Remote(url, persistEditionId)` — so the component never sees a `BookEdition`: the fallback ladder (chosen edition → default edition → fallback URL → nothing) runs in `:core:uibinding`'s `resolveCoverSource`, off the composition (§7 R9). Loading falls back to a shimmer placeholder. A final **coverless-title** rung via `coverlessTitle`: when no source resolves (or a known URL fails to load) and the data is not still loading, the cover falls back to the shared **Coverless title cover** component instead of a blank tile. **`model` is nullable, and every caller passes the nullable value straight through.** Because mapping happens in a collector (§7 R9), a cover model lands one state emission after the book it belongs to, so every list and sheet has a frame with an item but no cover. `Cover` answers that once: it reserves the 2:3 footprint its `modifier` gives it and draws nothing. Do **not** skip the item (the shelf then renders empty and pops in) and do **not** write a local placeholder. **A cover slot is never blank** — `coverlessTitle: String?` is a **required field on the model with no default**, precisely so this rule is enforced where the model is built rather than remembered: every surface rendering a real, readable cover must supply it, or the code does not compile. The one documented exception is the blurred decorative backdrop behind the book-detail hero (`GeneralBookInfoSection`'s `matchParentSize().blur(...)` layer): it is never read as a cover itself, so a title rendered there would just be blurred noise, and its mapping passes `coverlessTitle = null` explicitly, with a comment explaining why. **All treatment rides on `model.variant`** — a sealed `CoverVariant` of surface-named entries (`LibraryShelfItem`, `BookDetailHero`, `SessionPeekBar`, …) whose elevation, corner radius, shadow tint and Coil decode cap come from `CoverDimensions.forVariant`. No call site hand-tunes a cover, and tuning one surface cannot move another; widths stay in the caller's `Modifier`. Never use a raw image loader for covers — and where a surface needs the raw Coil request rather than the rendered component (the full-screen zoom/pan viewer, the Reading hero's blurred backdrop, both of which need their own aspect and `ContentScale`), use the public `rememberCoverImageRequest(model)`.

### Coverless title cover

`CoverlessTitleCover(title, modifier)` is the standalone component behind `Cover`'s coverless-title rung; every non-decorative cover call site reaches it that way rather than instantiating it directly (the tag-editor jacket and the explore hidden-suggestions shelf thumbnails at 48–52dp included). It renders the **monogram jacket**: a fixed-ink `MonogramCoverInk` panel (§2.1), an inset hairline `MonogramCoverForeground`-at-0.24-alpha border, and — at or above the component's full-title width floor — the **whole title** set large in italic Fraunces (`editorialTypography.headlineMedium`), centred and wrapped across lines. **Keyed purely on "no cover art resolves," never on release status** — an unreleased book with a real jacket shows that jacket like any other book; the monogram is reached only when no source resolves or a known URL fails to load, and only after loading has finished. It is **size-adaptive, with a graceful degrade to a single initial**: a `BoxWithConstraints` measures the tile it is given and derives the border inset, the full title's starting font size / line cap, and the single-initial fallback's font size purely from that measurement (`monogramCoverMetrics`, pure and independently tested). The full title renders via `TextAutoSize`, which shrinks the font further — down to a shared 10sp legibility floor — to fit the tile's measured width, ellipsizing if it still overflows the line cap; below the width floor (a tile too small to fit even a couple of legible words, e.g. a ~48dp shelf thumbnail) it falls back to the title's first letter set large instead, the original single-initial treatment. One component therefore serves everything from a 48dp shelf thumbnail (initial only) up through the widest real library grid tile (full title) with no per-call-site tuning. It imposes **no aspect ratio of its own**; it fills whatever box its `modifier` and the surrounding layout give it — `Cover` applies the 2:3 cover aspect on its own container before falling back to it.
