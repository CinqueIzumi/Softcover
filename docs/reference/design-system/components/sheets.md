# Components — Sheets

### Because-you-read genre picker

Explore's (feature-owned) "because you read {genre}" section lets the reader override the auto-derived genre via a **bottom sheet mirroring Library's own Shelves sheet pattern** (§5), rather than a bespoke dropdown or pill row. The anchor is a compact `eyebrowSmall` label naming the resolved genre with a trailing `primary` chevron (`"Genre · {genre}"`, uppercase); tapping it opens an `AdaptiveModalSheet`. The sheet's own header is a canonical editorial header (accent bar + "GENRE" eyebrow + "Pick a genre" headline — a short neutral category word rather than repeating the rail's "Because you read" name, which reads as redundant and option-like once opened inside the sheet) over a vertical list of hairline-divided rows — the Shelves sheet's row anatomy (`titleLarge` forced-italic label, promoted `primary` + trailing check glyph on the active row) minus the leading shelf-type glyph and trailing item count, neither of which a genre has. The first row is always "Auto (most-read)" (clearing the override back to the derived default, checked whenever the resolved genre isn't one of the switchable options); one row per switchable genre option follows. Tapping a row dispatches the selection and dismisses the sheet through `LocalModalSheetDismiss`; the sheet's open/closed flag is plain `remember`ed UI-local state. Hidden entirely when there are no genre options to switch between.

### Tag editor sheet

`TagEditorBottomSheet` (feature-local, `feature/book_detail`, `presentation/component/`) is the canonical surface for managing the user's *own* tags on a book (§3.5 modal sheet — editorial header first). Anatomy, a pinned opening over one scrolling body:

1. **Top bar** — the sheet's grabber is `AdaptiveModalSheet`'s own; a right-aligned primary **`Done`** text affordance (dispatched through `LocalModalSheetDismiss`) stays reachable from any scroll position.
2. **Header** — the canonical opening (accent bar, `YOUR TAGS` eyebrow, italic headline "Tag it your way.") composed locally rather than through `EditorialSectionHeader` (which has no trailing slot and can't tint a substring of its description) — the description names the book, with the title rendered in `primary` via an inline `AnnotatedString` span, and a 52×78dp `Cover` mini jacket (4dp corners, a light drop shadow, `coverlessTitle` fallback) sits trailing the text block.
3. **Add block** — the four fixed categories (**Genre / Mood / Tag / Content warning**) as a `FlowRow` of selectable `Chip`s, then a 48dp full-pill naming field on `surfaceContainerHigh`: a leading edit glyph, a borderless inline `BasicTextField` (the category-aware `namingHint` placeholder), and a trailing filled-primary **`Add`** pill that fades and scales in only once the trimmed draft is non-empty (and is not composed — not merely hidden — while empty, so it is never focusable/clickable at rest). `EditorialSearchField` hardwires a leading search glyph and a trailing clear-only button and has no leading-edit / trailing-commit slot, so this field is composed from the same primitives rather than bent to fit. IME **Done** commits too. Below the field sits the **suggestion cloud**: the user's own already-applied tags for the selected category (from the local vocabulary cache — there is no server-side tag *search*, since `_ilike` is disallowed by the API on compute-cost grounds), as tappable `Chip`s in an `ExpandableFlowRow` collapsed to two lines. It ranks by the user's personal usage frequency (then name) at rest and narrows to substring matches as they type, prefix matches tiered first. The cloud is **`FlowRowExpansion.Progressive(linesPerExpand = 3)` + `collapsible`** (§4): a gradual per-tap reveal keeps the whole vocabulary reachable without dumping it all at once, and "show less" returns it to two lines. It stays **category-scoped** — a tapped suggestion is filed under the selected category, so a cross-category cloud would silently mis-file tags and make the category chips above it meaningless. Nothing is capped in state: `computeTagSuggestions` returns the full ranked candidate set and the fold is the layout's alone. Naming a tag still works the same either way — the upsert reuses an existing tag of that name or mints a new one server-side.
4. **Collection** — tags render **grouped by category in fixed order** (Genre → Mood → Tag → Content warning; empty groups omitted), each group a ruled `eyebrowSmall` label + hairline `outlineVariant` rule + tabular count over a wrapping `FlowRow` of tag chips. A **tag chip** is a `surfaceContainerHigh` pill with a leading spoiler-toggle **eye** icon-button (open eye, `onSurfaceVariant` at ~0.7 alpha, unmarked; eye-off, `primary`, marked — flipping `UserTag.spoiler`) and a trailing **×** remove icon-button at the opposite end, so the two actions never crowd each other; a spoiler-marked name additionally takes the `spoilerEditorHighlight` wash. Both icon-only controls carry a verbose `contentDescription` ("Mark as spoiler" / "Marked as spoiler — tap to unmark" / "Remove {name}") and a `DesktopTooltip`. A just-added chip plays a brief fade + upward rise on the render pass that inserts it (never on the sheet's initial tags), reduced-motion gated via `playDecorativeMotion()`. An **empty state** (zero tags) centers a low-alpha `primary` `quoteGlyph` flourish (with `quoteGlyphSway()`) over "Nothing here yet." / "Name the first thing this book is to you."

**Scroll split.** Only the top bar and header are pinned; the add block and the collection share **one** scroll region beneath them. This is load-bearing, not incidental: an unbounded suggestion cloud inside a *pinned* add block would squeeze the collection's `weight(1f)` to nothing and clip the sheet, so a full reveal is only safe once the cloud can lengthen a scrolling page instead. It also keeps the naming field adjacent to the suggestions completing it, which a pinned field over a scrolling cloud would not. The trade is that the field can scroll out of view once the user is deep in their collection — acceptable, because reaching the field to type means scrolling back to it anyway. Do **not** reintroduce a second scroll region here: a nested scroller inside a drag-to-dismiss bottom sheet fights the sheet's own drag at scroll position 0.

The sheet is a dumb renderer — every add / remove / spoiler-toggle is reported through a callback and committed by the caller via the complete-set upsert (see "Your tags section" in patterns.md); the book title and displayed edition are render-only parameters extending the composable, not the TOAD state/action contract. Reach for it for self-tagging any entity; do not reuse it for the editorial (read-only) tag block. The naming-pill anatomy (tone-on-tone pill, leading glyph, fade-in trailing commit) and the leading-icon-toggle / trailing-remove chip anatomy are both reusable patterns beyond this sheet if another surface needs "name a thing" or "a per-item binary flag beside a removal" without reaching for `EditorialSearchField` or a same-weight toggle pill.

### Change edition sheet

`EditionBottomSheetSelector` is the **feature-local** (`feature/book_detail`, not shared — only Book Detail offers an edition switch) surface for picking which edition of a book the reader tracks. Anatomy:

1. **Header** — composed locally like the Choose-lists sheet: accent bar + `EDITIONS` eyebrow, italic "Change edition" headline, an italic description reading "{book title} · {author}" (`currentEdition.authorString`; the "· author" suffix drops when blank), and a trailing 56×84 `Cover` of the current edition.
2. **Search** — the house `EditorialSearchField`, not a boxed Material `OutlinedTextField` — tone-on-tone, full pill radius, leading search glyph, trailing clear-only ×, placeholder "Search by ISBN or publisher".
3. **Count label** — "{n} EDITIONS", uppercase `eyebrowSmall`/Inter, `onSurfaceVariant`.
4. **Edition cards** (the **edition-difference card** — reusable anatomy for any "pick among near-identical items" list) — one `LazyColumn` row per edition, **differences-first**: a 44×66 `Cover`, then a leading **format icon + label** row (the format is the differentiator, so it leads — `readingFormat` maps to a glyph: audiobook → headset, e-book → the library-books glyph (no dedicated ebook glyph exists), physical/both → the menu-book glyph; the label is `edition.format` when set, else `readingFormat.label`), a single **tabular** meta line (`publisher · year · pages`, pages swapped for a duration on an audiobook via the foundation `toHoursMinutesSeconds()` — never hand-rolled — with unknown parts dropped), an **ISBN whisper** demoted to `onSurfaceVariant` at 70% alpha, and — when owned — "You own this edition" in `primary` with a leading bag glyph. Card state: `selected` → `surfaceContainerLow` fill + a filled `primary`/`onPrimary` check circle trailing the format row; **owned** or **selected** → a 1.5dp `primary` inset outline (both read as "this edition matters"); the **currently-tracked** edition (`edition.id == currentEdition.id`, when not itself selected) → a quiet `surfaceContainerHigh` "TRACKING NOW" chip instead of the check. Tapping a card sets local `selectedEdition` state (not part of the TOAD contract).
5. **Confirm foot** — a full-width filled `RhaydusButton`, label **"Track this edition"** (edition-agnostic — not "Confirm edition"), enabled once a different edition than `currentEdition` is selected and not loading. Loading and empty-search states use the house wavy indicator (never a circular spinner) and "No editions match your search" in `body`/`onSurfaceVariant`.

Reach for the edition-difference card anatomy for any other "pick the right variant" list; do not reuse `EditionBottomSheetSelector` itself outside Book Detail.

### Loading sheet

`LoadingSheet(model: LoadingSheetUiModel, onEvent)` (`core:component`, `sheet/`) is the full-screen blocking wavy progress surface for an unavoidable wait, used by onboarding's initial library pull; it reports `LoadingSheetEvent.LoaderFinished` once the bar settles. Prefer inline shimmer on cards when the wait is short or the surface can stay interactive.

### Date picker dialog

`SoftcoverDatePickerDialog` (`core:component`, `dialog/`) is the canonical calendar dialog for picking a single day, and the deadline picker on book detail is its first consumer. It takes `initialDate: LocalDate?` (today when null) and hands back a `LocalDate` through `onConfirm`; a cancel — including the degenerate no-selection case — routes to `onDismiss`. **The point of the component is that a call site never touches epoch millis.** Material 3's `DatePickerState` defines `initialSelectedDateMillis` / `selectedDateMillis` as *UTC* milliseconds, so converting either side through the device timezone shifts the calendar day — west of UTC the confirmed date lands a day early, east of it the dialog opens on the day (and at a month boundary the month) before the one it was given. That contract is owned once, by the `internal` `toPickerMillis()` / `toPickerLocalDate()` helpers in `dialog/PickerDates.kt`. Any new "pick a date" surface reaches for this dialog; hand-rolling a `DatePickerDialog` and converting the millis at the call site is the bug it exists to prevent.

### Update progress sheet

`UpdateProgressBottomSheet` (`core:component`, `progress/`) is the modal sheet for editing reading progress. Hosts the canonical `pages | percentage | time` segmented switcher with a hero numeric input, an editorial suffix line, and a wavy progress bar. Driven by `ProgressSheetUiModel` + one `onEvent: (ProgressSheetEvent) -> Unit` — the **first component in the library to take the contract's single sealed event lambda** (§7.2 R1); `ProgressSheetTab` is a library type and `selectedTab` rides on the model, because §7.1's signature admits no second parameter beside the model. The switcher is **format- and total-aware**, decided by the model rather than the sheet: the model's `ProgressSheetMedium` is a sealed `Paged(totalPages, currentPage)` | `Timed(totalSeconds, currentSeconds)`, so an audiobook cannot carry a page count and a print edition cannot carry a runtime. `time` is the primary unit for `Timed` and `pages` for `Paged` (the `:core:uibinding` mapper picks the branch off `BookEdition.isAudiobook`, keyed on the edition's `ReadingFormat`, not on whether a duration happens to be present), and `percentage` is offered **only when `medium.hasKnownTotal`** — without a total a fraction can only ever resolve to 0, so the tab is hidden rather than shown broken. When that total is unknown the sheet drops to the primary unit alone, hides the "of N …" suffix and the progress bar, and accepts free numeric/time entry (no clamp-to-total). New "edit a single number on a book" surfaces should look at this sheet before inventing a new one. **Stepper circles.** The Page and Percentage tabs flank the hero number with a pair of 44dp circular `surfaceContainerHigh` `−` / `+` steppers (primary glyph), stepping the value by 1 (page or percent) and reusing the same clamp bounds (`[0, total]` / `[0, 100]`) the typed-entry path already enforces. The Time tab carries the same stepper pair around its minutes field only, stepping by 1 minute — hours and seconds stay typed-entry only. A stepper tap writes straight into the tab's existing `TextFieldValue` state, so it composes with typed entry rather than branching around it. **Mark as read.** A standard secondary action, present on **every** progress sheet — an outlined `RhaydusButton` (`ButtonStyle.OUTLINED`, a check icon, label "Mark as read") sits below the tab content's own "Update progress" filled action. It is reported as `ProgressSheetEvent.MarkAsReadRequested(actionAt)`, and because the caller's `when (event)` over the sealed type is exhaustive, a call site that fails to handle it **does not compile**. Dismissing the sheet afterwards is the host's job, not the sheet's: both consumers dispatch their mark-as-read path *and* their dismiss action from that one branch. Both current consumers route it to their existing per-book mark-as-read path rather than introducing a new one: Reading wires it to the same commit choreography a book's row/hero "mark as read" affordance always uses (haptic, burst, bottom-bar pulse, and the "slide to shelf" follow-through when motion is enabled, §2.5); Book Detail dispatches the same action its Shelve control's "Read" row fires, whose commit haptic + `MarkAsReadBurst` celebration is already driven screen-wide off the ScreenModel's mark-as-read event, so the sheet gets the identical celebration for free.

### Choose-lists sheet

`ChooseListsBottomSheet` is the canonical shared surface for adding/removing one or more books to the user's custom lists (§3.5 modal sheet — editorial header first). It is a **shared `core:component`** component (`lists/`) consumed by both `book_detail` (single book) and the library **bulk-select** pattern (§5, a `Set<bookId>`). Driven by `ChooseListsUiModel` + one `onEvent: (ChooseListsEvent) -> Unit` (§7.2 R1). Who is being shelved is a sealed `ChooseListsVariant` — `SingleBook(name)` or `ManyBooks(bookCount, coverCount)`. It reads as an **editorial index of shelves**, not a checkbox list. Anatomy:

1. **Header** — composed locally (not `EditorialSectionHeader`, which can't tint a substring of its headline): accent bar + `LISTS` eyebrow, an italic headline naming the act — "Shelve **{book title}**" (single, the title in a `primary` `AnnotatedString` span) or "Shelve **{n} books**" (bulk) — both read off `ChooseListsVariant.name` — and an italic description (single: "Tap a list to file it here — tap a filled one to take it off. Saved as you go."; bulk: "A part-filled list adds the rest first — then a second tap takes all three off."). A trailing jacket names the book(s) at the top of the sheet: a single 56×84 cover for one book, or a rotated 3-jacket stack (52×78 each, −8°/+4°/0° behind→front) for bulk. The jackets are already-resolved `CoverUiModel`s carried on the variant itself — `SingleBook(name, cover)` / `ManyBooks(bookCount, covers)` — so a single book cannot express a three-jacket stack and the header art cannot disagree with the caption arithmetic. The sheet owns the whole treatment: the width and rotation ride in the `Modifier` it applies, and the elevation, radius and shadow come from `CoverVariant.ChooseListsSingleJacket` / `ChooseListsStackJacket` via `CoverDimensions`. **`covers` may be empty**, and the stack then collapses to one *un-rotated* coverless jacket the sheet builds itself: a lone tilted placeholder reads as a rendering fault rather than as a stack, so the rotation only applies once there is more than a placeholder to stack. Covers travel on the variant itself, not through a separate jacket slot.
2. **Rows** — a `LazyColumn` of the user's custom lists rendered as a **ruled index**: each row draws its own top `outlineVariant` hairline (so the list reads as a contents page, not boxed cards), a leading 23dp **bookmark** glyph, an italic `titleLarge`-forced-italic list name ("set like a chapter" — the same treatment the Shelves sheet's rows use, §5), an uppercase `eyebrowSmall` caption, and a trailing **reversible membership control**. Membership is the **tristate** model — `ListMembership.NONE` / `PARTIAL` / `ALL`, `PARTIAL` meaning some-but-not-all of the selected books are in that list. It resolves in the `:core:uibinding` mapper, per row, along with the row's `caption` and `actionLabel` strings (R4) — never in the component — and the sheet renders one `ChooseListsRowUiModel` per row; `membership` still rides on the row because it selects *which* trailing control renders, not just its label. Tapping a row commits toward the larger end (`PARTIAL` → `ALL`, `ALL` → `NONE`); every toggle is **instant/optimistic — there is no save button**. A row mid-mutation (its id in `listsBeingMutated`) is tap-disabled and shows the house wavy indicator, never a circular spinner.
   - **Bookmark glyph**: `ALL` → filled `primary` bookmark; `NONE` → `outline`-stroke bookmark; `PARTIAL` (bulk only) → a hand-drawn partial mark (a 19×23dp `primary`-bordered box with a short horizontal `primary` bar) — reusable anatomy for any tri-state row indicator beyond this sheet.
   - **Caption**: single = "{n} BOOKS"; bulk appends the membership phrase — `ALL` → "ALL {k} HERE", `PARTIAL` → "{matching} OF {k} HERE" (tinted `primary`), `NONE` → "NONE YET" (`k` = the selected-book count).
   - **Trailing control** (the **reversible membership pill** — reusable beyond this sheet): `ALL` → a removable `primaryContainer`/`onPrimaryContainer` chip reading "On the list ×" (single) or "On all {k} ×" (bulk), the × a 12dp `Close` glyph; `PARTIAL` (bulk) → a **filled** `primary`/`onPrimary` pill "+ Add the other {k-matching}" (the tri-state's next tap spelled out, not "1 of 3 here"); `NONE` → a quiet `outlineVariant`-bordered pill "+ Add" (single) or "+ Add all {k}" (bulk), with the leading "+" tinted `primary`. The whole row is the tap target; the pill is display-only.
3. **Create row** — "Create a new list" (`onCreateNewListClick`), styled as a quiet dot row: a 26×26 `surfaceContainerHigh` circle holding a `primary` "+", then the label in `primary`. No hairline card.

The sheet is a **dumb renderer** — every toggle and the create action are reported as one `ChooseListsEvent`, with `MembershipToggled` carrying both the row's `listId` and its current `membership` (what the host branches on); the caller owns the `AddBookToListUseCase` / `RemoveBookFromListUseCase` writes and decides whether to stay open for consecutive adds. Reach for it for any add-to-list affordance; do not build a per-screen list picker.
