# Components — Sheets

### Because-you-read genre picker

Explore's (feature-owned) "because you read {genre}" section lets the reader override the auto-derived genre via a **bottom sheet mirroring Library's own [Shelves sheet](../patterns/library.md#shelves-sheet-library-mobile) pattern**, rather than a bespoke dropdown or pill row. The anchor is a compact `eyebrowSmall` label naming the resolved genre with a trailing `primary` chevron (`"Genre · {genre}"`, uppercase); tapping it opens an `AdaptiveModalSheet`. The sheet's own header is a canonical editorial header (accent bar + "GENRE" eyebrow + "Pick a genre" headline — a short neutral category word rather than repeating the rail's "Because you read" name, which reads as redundant and option-like once opened inside the sheet) over a vertical list of hairline-divided rows — the Shelves sheet's row anatomy (`titleLarge` forced-italic label, promoted `primary` + trailing check glyph on the active row) minus the leading shelf-type glyph and trailing item count, neither of which a genre has. The first row is always "Auto (most-read)" (clearing the override back to the derived default, checked whenever the resolved genre isn't one of the switchable options); one row per switchable genre option follows. Tapping a row dispatches the selection and dismisses the sheet through `LocalModalSheetDismiss`; the sheet's open/closed flag is plain `remember`ed UI-local state. Hidden entirely when there are no genre options to switch between.

### Tag editor sheet

`TagEditorBottomSheet` (feature-local, `feature/book_detail`, `presentation/component/`) is the canonical surface for managing the user's *own* tags on a book (§3.5 modal sheet — editorial header first). Anatomy, a pinned opening over one scrolling body:

1. **Top bar** — the sheet's grabber is `AdaptiveModalSheet`'s own; a right-aligned primary **`Done`** text affordance (dispatched through `LocalModalSheetDismiss`) stays reachable from any scroll position.
2. **Header** — the canonical opening (accent bar, `YOUR TAGS` eyebrow, italic headline "Tag it your way.") composed locally rather than through `EditorialSectionHeader` (which has no trailing slot and can't tint a substring of its description) — the description names the book, with the title rendered in `primary` via an inline `AnnotatedString` span, and a 52×78dp `Cover` mini jacket (4dp corners, a light drop shadow, `coverlessTitle` fallback) sits trailing the text block.
3. **Add block** — the four fixed categories (**Genre / Mood / Tag / Content warning**) as a `FlowRow` of selectable `Chip`s, then a 48dp full-pill naming field on `surfaceContainerHigh`: a leading edit glyph, a borderless inline `BasicTextField` (the category-aware `namingHint` placeholder), and a trailing filled-primary **`Add`** pill that fades and scales in only once the trimmed draft is non-empty (and is not composed — not merely hidden — while empty, so it is never focusable/clickable at rest). `EditorialSearchField` hardwires a leading search glyph and a trailing clear-only button and has no leading-edit / trailing-commit slot, so this field is composed from the same primitives rather than bent to fit. IME **Done** commits too. Below the field sits the **suggestion cloud**: the user's own already-applied tags for the selected category (from the local vocabulary cache — there is no server-side tag *search*, since `_ilike` is disallowed by the API on compute-cost grounds), as tappable `Chip`s in an `ExpandableFlowRow` collapsed to two lines. It ranks by the user's personal usage frequency (then name) at rest and narrows to substring matches as they type, prefix matches tiered first. The cloud is **`FlowRowExpansion.Progressive(linesPerExpand = 3)` + `collapsible`** (§4): a gradual per-tap reveal keeps the whole vocabulary reachable without dumping it all at once, and "show less" returns it to two lines. It stays **category-scoped** — a tapped suggestion is filed under the selected category, so a cross-category cloud would silently mis-file tags and make the category chips above it meaningless. Nothing is capped in state: `computeTagSuggestions` returns the full ranked candidate set and the fold is the layout's alone. Naming a tag still works the same either way — the upsert reuses an existing tag of that name or mints a new one server-side.
4. **Collection** — tags render **grouped by category in fixed order** (Genre → Mood → Tag → Content warning; empty groups omitted, any other category folds into a trailing "Other" group), each group a ruled `eyebrowSmall` label + hairline `outlineVariant` rule + tabular count over a wrapping `FlowRow` of `Chip`s using `ChipVariant.Editable` (chip contract in `core:component/chip`). A just-added chip plays a brief fade + upward rise on the render pass that inserts it (never on the sheet's initial tags), reduced-motion gated via `playDecorativeMotion()` and tracked by `BookDetailUiState.newlyAddedTagKey` rather than composition state. An **empty state** (zero tags) centers a low-alpha `primary` `quoteGlyph` flourish (with `quoteGlyphSway()`) over "Nothing here yet." / "Name the first thing this book is to you."

**Scroll split.** Only the top bar and header are pinned; the add block and the collection share **one** scroll region beneath them. This is load-bearing, not incidental: an unbounded suggestion cloud inside a *pinned* add block would squeeze the collection's `weight(1f)` to nothing and clip the sheet, so a full reveal is only safe once the cloud can lengthen a scrolling page instead. It also keeps the naming field adjacent to the suggestions completing it, which a pinned field over a scrolling cloud would not. The trade is that the field can scroll out of view once the user is deep in their collection — acceptable, because reaching the field to type means scrolling back to it anyway. Do **not** reintroduce a second scroll region here: a nested scroller inside a drag-to-dismiss bottom sheet fights the sheet's own drag at scroll position 0.

The sheet is a dumb renderer — every add / remove / spoiler-toggle is reported through a callback and committed by the caller via the complete-set upsert (see [Your tags section](../patterns/book-detail.md#your-tags-section)); the book title and displayed edition are render-only parameters extending the composable, not the TOAD state/action contract. Reach for it for self-tagging any entity; do not reuse it for the editorial (read-only) tag block. The naming-pill anatomy (tone-on-tone pill, leading glyph, fade-in trailing commit) and the leading-icon-toggle / trailing-remove chip anatomy are both reusable patterns beyond this sheet if another surface needs "name a thing" or "a per-item binary flag beside a removal" without reaching for `EditorialSearchField` or a same-weight toggle pill.

### Change edition sheet

`EditionBottomSheetSelector` is the **feature-local** (`feature/book_detail`, not shared — only Book Detail offers an edition switch) surface for picking which edition of a book the reader tracks. Anatomy:

1. **Header** — composed locally like the Choose-lists sheet: accent bar + `EDITIONS` eyebrow, italic "Change edition" headline, an italic description reading "{book title} · {author}" (`currentEdition.authorString`; the "· author" suffix drops when blank), and a trailing 56×84 `Cover` of the current edition.
2. **Search** — the house `EditorialSearchField`, not a boxed Material `OutlinedTextField` — tone-on-tone, full pill radius, leading search glyph, trailing clear-only ×, placeholder "Search by ISBN or publisher".
3. **Count label** — "{n} EDITIONS", uppercase `eyebrowSmall`/Inter, `onSurfaceVariant`.
4. **Edition cards** (the **edition-difference card** — reusable anatomy for any "pick among near-identical items" list) — one `LazyColumn` row per edition, **differences-first**: a 44×66 `Cover`, then a leading **format icon + label** row (the format is the differentiator, so it leads — `readingFormat` maps to a glyph: audiobook → headset, e-book → the library-books glyph (no dedicated ebook glyph exists), physical/both → the menu-book glyph; the label is `edition.format` when set, else `readingFormat.label`), a single **tabular** meta line (`publisher · year · pages`, pages swapped for a duration on an audiobook via the foundation `toHoursMinutesSeconds()` — never hand-rolled — with unknown parts dropped), an **ISBN whisper** demoted to `onSurfaceVariant` at 70% alpha, and — when owned — "You own this edition" in `primary` with a leading bag glyph. Card state: `selected` → `surfaceContainerLow` fill + a filled `primary`/`onPrimary` check circle trailing the format row; **owned** or **selected** → a 1.5dp `primary` inset outline (both read as "this edition matters"); the **currently-tracked** edition (`edition.id == currentEdition.id`, when not itself selected) → a quiet `surfaceContainerHigh` "TRACKING NOW" chip instead of the check. Tapping a card sets local `selectedEdition` state (not part of the TOAD contract).
5. **Confirm foot** — a full-width filled `RhaydusButton`, label **"Track this edition"** (edition-agnostic — not "Confirm edition"), enabled once a different edition than `currentEdition` is selected and not loading. Loading and empty-search states use the house wavy indicator (never a circular spinner) and "No editions match your search" in `body`/`onSurfaceVariant`.

Reach for the edition-difference card anatomy for any other "pick the right variant" list; do not reuse `EditionBottomSheetSelector` itself outside Book Detail.

### Choose-lists sheet

`ChooseListsBottomSheet` (`core:component`, `lists/`) reads as an editorial index of shelves, not a checkbox list. **Header** — accent bar + `LISTS` eyebrow, an italic "Shelve {name}" headline, and a trailing jacket: a single 56×84 cover, or a rotated 3-jacket stack (52×78 each, −8°/+4°/0°) for a bulk selection — `covers` may be empty, collapsing to one un-rotated coverless jacket rather than a lone tilted placeholder. **Rows** — a ruled index (a top hairline per row, no cards): a leading 23dp bookmark glyph (filled `primary` / outline / a hand-drawn 19×23dp partial mark — reusable anatomy for any tri-state row indicator beyond this sheet), an italic chapter-style name, an eyebrow caption, and a trailing **reversible membership pill** (also reusable beyond this sheet): a removable filled chip, a filled "+ Add the other N" pill, or a quiet outline "+ Add" pill. **Create row** — a quiet dot row reading "Create a new list", no hairline card.
