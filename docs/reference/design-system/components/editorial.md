# Components — Editorial

### Drop-cap text

`DropCapText` renders editorial body prose with a 3-line drop-cap on the first letter, tinted `primary` by default. It lives in the **foundation `designsystem-editorial`** (`nl.rhaydus.designsystem.editorial.component`). The drop-cap font size is `bodyStyle.lineHeight * 3 * 0.92`; the first three lines of body text indent past the cap, and lines four onward resume at full width. Line spacing is uniform across that seam — the cap glyph's own metrics (Fraunces runs taller than the three body lines it spans) only grow the component's total height, never the gap between the indented and full-width runs. Skips leading whitespace and punctuation when picking the letter; falls back to a plain `Text` for empty or letter-less bodies. Pass `dropCapFontFamily = displayFontFamily()` to render the cap in Fraunces (the Softcover editorial display face) — the parameter defaults to `null` (same family as the body) so the app must supply the font explicitly. Reach for it on book-detail descriptions; do not apply it to inline metadata or to bodies inside cards where the cap would dominate the tile.

### Editable hero-stat field

`HeroStatNumberField` is the shared "edit a single number framed as a hero" control (with its `EditorialSuffix` caption): a borderless `BasicTextField` rendered in the editorial `statLarge` face, cursor tinted `primary`, width sized to the character count so it reads as a hero numeral rather than a boxed form field. Both live in the **foundation `designsystem-editorial`** (`nl.rhaydus.designsystem.editorial.component`). It is the canonical input behind both the Update progress sheet and Focus Mode's page entry. Reach for it for any number the user edits in a hero context; **never** use a bordered `OutlinedTextField`/`TextField` for that role — the box clashes with the editorial register.

### Star rating input

`StarRatingInput` is the foundation `designsystem-core` interactive personal-rating control (`nl.rhaydus.designsystem.component.StarRatingInput`): a row of five `ic_star_filled` glyphs the user rates against in half-star steps. Empty stars are `onSurfaceVariant` at low alpha by default; the filled portion is the shared `RatingGold` brand colour (the same gold the read-only community/review rating glyphs use — never re-declare the hex at a call site). Partial fills are drawn by clipping the gold glyph to a fraction of its width, so a `4.5` reads as four-and-a-half stars. Tapping a star commits that value (left half → `.5`, right half → whole); dragging horizontally scrubs and fires one `tickle` haptic (§2.5) per half-step crossing. The committed value is reported through `onRatingChange` once per gesture — on tap or on drag release, never mid-drag. Softcover supplies the brand bits at each call site — `starIcon = drawableIconResource(icon = SoftcoverIcon.StarFilled, …)` and `filledColor = RatingGold`. It appears in exactly two places, at two different sizes and two different interaction modes: **inside `VerdictSheet`** (42dp, fully interactive — the *only* place a rating is set or changed) and **inside `VerdictBlock`** (22dp filled / 30dp empty, `enabled = false` with an explicit `emptyColor = outlineVariant` — read-only display; tapping the surrounding card, not the stars, opens the sheet).

### Personal review section

The book-detail entry point into the review editor, in the Yours lens. A bar-less in-flow `YOUR REVIEW` label (§2.3's no-bar register) with a trailing primary-coloured **`Edit`** affordance (shown only once a review exists) heads a single tappable card: `surfaceContainerHigh` / **"Write a few words…"** editorial prompt when no review exists, or a `surfaceContainer`, 20dp-radius, 18dp-padded card holding the review rendered via `RichText` (upright editorial body), clipped to `REVIEW_COLLAPSED_LINES`, with a quiet "contains spoilers" footnote when the whole-review flag is set. Tapping anywhere on the card — including the rendered text, except a concealed spoiler span — opens the review editor sheet seeded with the current structured review. It sits directly beneath the your-tags section on the Read shelf so a reader's rating and words live together. The review rides on the cached `user_book` row (as a structured `review_slate`), so it arrives with the book and reflects edits made elsewhere — no separate load, no skeleton, no flash.

### Browse-by-mood grid

Explore's (feature-owned) 2-column mood-tile grid (`MoodGrid`/`MoodTile`): tiles are `16dp`-padded, `104dp`-min-height, `16dp`-radius, and each row is measured at `IntrinsicSize.Max` with both cells `fillMaxHeight()` so two titles wrapping to a different line count still land at the same row height. Anatomy top-to-bottom: a `MOOD` eyebrow + a small search glyph on one row, then the title (the mood-tile title exception, §2.2) and a book-count subline (`formatGroupedNumber`, grouped thousands — never a hand-rolled digit string). Ink cycles through the four fixed looks in §2.1 by tile position (index mod 4), repeating past the fourth tile rather than introducing a new colour. Mood labels arrive from the API lowercase; the render layer title-cases each whitespace-separated word before it reaches a `Text` — the domain model itself is never mutated. A tap always runs a mood-filtered search (never its own feed rail).

### Verdict sheet

`VerdictSheet` (`core:component`, `verdict/`) is the combined rating-and-review surface. It is a **shared cross-feature component** — consumed by both `feature/book_detail` (reopened from the book page in `EDIT` context) and `feature/reading` (raised once in `FINISHED` context on a genuine mark-as-read transition, §5 "Verdict prompt") — following the same shared-stateless-component pattern as `ChooseListsBottomSheet` / `UpdateProgressBottomSheet`: each feature hosts it off its own TOAD state and saves through the shared `core:book` `SaveBookVerdictUseCase`. The sheet is a **full-height, three-band layout** — a fixed dismiss header, a scrolling middle, and a pinned action footer — so the primary action is never buried below the fold (the same `fillMaxHeight` + `weight(1f)`-scroll-region + fixed-chrome shape as `EditionBottomSheetSelector`). Band by band: (1) **fixed header** — a right-aligned top-bar dismiss text ("Not now" / "Cancel") that stays reachable from any scroll position; (2) **scrolling middle** (`weight(1f).verticalScroll`) — a centred 2:3 book jacket, 96dp wide, in the sheet's **`cover` slot** — the sheet owns the slot's width, the caller supplies the image (a `Cover`), because resolving a cover needs the chosen edition, the book's default, a fallback URL and a locally persisted file, none of which a component may know (R4) — so the verdict visibly belongs to a book, the canonical `EditorialSectionHeader` (accent bar + eyebrow + italic headline naming the book + an optional description), a 42dp `StarRatingInput`, the **score line + verdict caption** (below), an "In your words" label directly heading a borderless tone-on-tone `BasicTextField` on `surfaceContainerHigh` (no border ring), then the **review formatting toolbar** + its "Select text…" hint *below* the field (so the label sits against the field it names rather than being pushed off it by the toolbar), and a "Contains spoilers" `Switch` row; (3) **pinned footer** — a hairline `HorizontalDivider` over a full-width filled **Save** and — only in `EDIT` context with an existing review — a text **Delete review**, always visible and (via `imePadding` on the sheet body) parked just above the keyboard while the review is edited. Rating and review are both a **local draft**: `StarRatingInput`'s `onRatingChange` only updates the draft, and nothing reaches `onSave` until Save is tapped, so leaving with just a rating, just a review, or neither always works — Save is never disabled. The **score line + verdict caption** (`Inter` "YOUR {score} / 10" over an italic `headlineSmall` margin-note caption — one of ten hand-written phrases keyed to the /10 score, e.g. "One that lingers." at 8, falling back to "How was it?" before a rating exists) crossfades with a slight rise on every rating change (`AnimatedContent` keyed on the derived score, ~300ms, `playDecorativeMotion()`-gated). `context: VerdictSheetContext` (`FINISHED` / `EDIT`, `core:component` `verdict/`) swaps copy only — eyebrow, headline, description, dismiss label, save label — never the anatomy. Reach for it for any surface that lets the reader rate and/or review a book; never reintroduce a rating-only or review-only sheet.

### Verdict block

`VerdictBlock` (`core:component`, `verdict/`) is the book-page card combining rating and review into one surface, on a `surfaceContainer` card (20dp radius). **Empty** (no rating, no review): read-only outline stars (30dp) + an italic invitation ("Rate it and say a few words…") + a quieter hint line. **Filled** (a rating and/or a non-blank review — the two are independent; a rating-only or review-only verdict still renders the filled anatomy, just omitting the piece that has no content): a read-only gold `StarRatingInput` (22dp) + the score line when rated, a hairline `outlineVariant` divider when both a rating and a review are present, the review rendered through `RichText` (up to 8 lines, markdown + spoiler-cover), and a trailing "TAP TO EDIT" hint. An "Edit" text link appears beside the "YOUR VERDICT" eyebrow once any verdict content exists; the whole card is also clickable (`onEditClick`), which the caller wires to open `VerdictSheet` in `EDIT` context. Rating and review are **never edited inline** on the book page — this block is read-only end to end.
