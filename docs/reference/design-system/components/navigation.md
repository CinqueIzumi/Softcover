# Components — Navigation & chrome

### Editorial search field

`EditorialSearchField` is the canonical *inline* search input for surfaces that carry their own editorial header rather than a Material search top bar: a fully-rounded `surfaceContainer` pill holding a leading search glyph, a single-line `BasicTextField`, and a trailing clear (✕) button that appears only once there is a query. It lives in the **foundation `designsystem-editorial`** (`nl.rhaydus.designsystem.editorial.component`) and is consumed by the desktop Library and desktop Explore headers. The caller supplies the icons as `RhaydusIconResource` (`searchIcon`, `clearIcon`); the empty-state hint adapts via `placeholder` ("Search your collection" on Library, "Search books, authors…" on Explore). Library renders it **persistently** on both mobile and desktop — no toggle icon, no hidden search affordance — per the masthead pattern (a large collection needs a findable front door). Reach for it when a static editorial layout wants a persistent search field beneath its title; use the **Search top app bar** instead when search *is* the app bar (the mobile pattern).

### Bottom navigation

Tab destinations for the four roots, the **compact-width** chrome (§2.7 window size). Provided as a docked bar (full-width, attached to the system inset) and a floating toolbar variant; pick docked unless the screen explicitly calls for a hovering bar over scrolling media. The two are **placements of one host**, not two shells: `CompactNavShell` renders a single foundation `BottomBarScaffold` and maps the reader's `BottomBarStyle` preference onto `BottomBarPlacement.DOCKED` / `.OVERLAY`, so flipping the preference re-places the bar without relocating the tab body (which would tear down and rebuild the live tab). The rendered bar itself is **app-shell code, not a `core/component/` component** — `DockedBottomNavigationBar` / `BottomFloatingBar` live at the orchestration tier (`orchestration/presentation/`) alongside the `TabNavigator` host, because they enumerate the concrete feature tabs. Reusable building blocks they rely on (`RhaydusIconToggleButton`, icon/color roles) stay in `core`. The floating variant's tap shield (a transparent `clickable` around the pill, so taps in the gaps never fall through to the content scrolling beneath) is part of the bar chrome, not the host.

### Navigation rail

The **medium-width** chrome (§2.7): a vertical `NavigationRail` that replaces the bottom bar between 600 and 840dp. Same destinations, selection, app-update badge, and library pulse as the bottom bars. It is **app-shell code at the orchestration tier**, like the bottom bars — it enumerates the concrete feature tabs; the rail and the bottom bars and sidebar below are all driven by one shared `rememberNavItems()` source (`orchestration/presentation/`) so selection, badge, and pulse can never drift between them.

### Editorial sidebar

The **expanded-width** chrome (§2.7): a permanent sidebar (`>= 840dp`) carrying the app wordmark in the editorial `pageTitle` voice over the four destinations, each a selectable row in the app's selected-chip colours (`secondaryContainer` / `onSecondaryContainer` when active, `onSurfaceVariant` idle). Replaces the rail. App-shell code at the orchestration tier, driven by the same `rememberNavItems()` source as the rail and bottom bars.

### Session peek bar

`SessionPeekBar` (`feature/session`, `presentation/component/`) is the persistent live-timer bar that rides above the bottom navigation whenever a reading session is active. Anatomy: a `surfaceContainerHigh` rounded bar holding a 32dp `Cover` thumbnail, the book title (`titleSmall`, single line), a live `H:MM:SS` timer beneath it (or `Paused · …` when paused), then inline pause/resume and stop `IconButton`s. The whole bar is tappable and opens Focus Mode. It reads the app-scoped `ActiveSessionController` (never its own session state) and renders nothing when no session is active, sliding in/out with `slideInVertically + fadeIn` / `slideOutVertically + fadeOut`. Pause/resume fires a `select` haptic, stop fires `threshold` (§2.5). It is mounted once, above the nav in both the docked and floating bar styles — never duplicated per screen. On the **wide shell** (medium/expanded, where there is no bottom bar for a floating pill to ride over) it renders its **flush** form (`flush = true`): an edge-to-edge strip with square corners and a leading top hairline, docked at the foot of the content pane — the desktop now-playing convention — rather than the rounded floating card the compact bottom bar carries. Reach for it only as the global session surface; do not build a second timer bar.

### Settings menu row

`SettingsMenuRow` (`feature/settings`, `presentation/screen/section/`, `commonMain`, `internal`) is the one borderless, hairline-separated row anatomy behind both the mobile Settings menu and the About screen's Credits/Source/Contact groups. Anatomy: a top `outlineVariant` hairline drawn on **every** row including the first (so a run reads as one continuous hairline list, never a boxed `Surface`/card), a 42dp `surfaceContainerHigh` icon tile (12dp radius) holding a `primary`-tinted 22dp glyph, an Inter `titleMedium` label (never italic) over an italic Fraunces `bodySmall` gloss that wraps rather than truncates, and a trailing `SettingsRowAccessory` — `Chevron` (a sub-page push), `External` (`SoftcoverIcon.OpenInNew`, hands off to `openUrl`), or `None`. `onClick` doubles as the selectability switch: `null` renders a non-interactive row with the title wrapped in a `SelectionContainer` (the Discord-username row uses this for tap-to-copy-free text selection, since Compose Multiplatform's clipboard-write path has no common-code `ClipEntry` constructor). Every interactive row presses through `pointerHandCursor()` + `pressScale` + an animated `surfaceContainer` wash gated on `playDecorativeMotion()` — the row's only container tint. The editorial accent-bar + eyebrow ceremony belongs to the group header (`SectionHeader`) once per group, never per row. Stays private to `feature/settings`: no other feature uses this anatomy.
