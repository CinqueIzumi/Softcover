# Components — States & feedback

### Inline error state

`InlineErrorState(message, onRetry, modifier)` is the standard inline surface for a load or submit failure. It renders the `message` in the `error` color role (editorial `bodySmall` face, centered) and a full-width outlined **Retry** `RhaydusButton` (size S) below it, vertically centered within the space the caller supplies via `modifier`. It is consumed by any screen whose TOAD `UiState` carries a `String?` error-slot — drop it where the normal content would appear, not as an overlay. The caller passes a `() -> Unit` retry lambda that re-dispatches the appropriate `UiAction`; the component is oblivious to the action type. Reach for it on any inline load/submit-failure surface: explore search errors, onboarding key validation, and future `String?`-slotted screens. Do not hand-roll a per-screen error layout. It is the foundation `designsystem-core` component (`nl.rhaydus.designsystem.component.InlineErrorState`); the editorial `bodySmall` face is supplied by Softcover via the `textStyle` param (the foundation default is plain Material `bodySmall`), and the `retryLabel` default `"Retry"` is kept.

### Pull-to-refresh indicator

The Material 3 Expressive `ContainedLoadingIndicator` inside a `PullToRefreshDefaults.IndicatorBox` is the canonical pull-to-refresh affordance. This is a deliberate exception to the "wavy progress, always" rule (DS §2.5, §6): the wavy circular indicator visually competes with the pull gesture's own arc and reads as off at this size, while the contained loading indicator's morphing shape carries the same expressive character without the conflict. Reach for the wavy primitive everywhere else progress is shown.

### Pull-to-refresh eyebrow

`PullToRefreshEyebrow` is the canonical eyebrow for any screen that hosts a pull-to-refresh surface. It lives in the **foundation `designsystem-editorial`** (`nl.rhaydus.designsystem.editorial.component`). It renders the same accent-bar + eyebrow anatomy as a static `SectionLabel`, but swaps the label to a contextual refresh copy ("Refreshing your shelf…", "Catching up on your reading…") while the user pulls and during the subsequent refresh, then flashes the base label briefly in italic on revert. Wired internally: the eyebrow consumes the same `PullToRefreshState` already passed to `PullToRefreshBox`, listens to its `distanceFraction`, and fires a single `threshold` haptic at the trigger crossing (re-armed once the gesture relaxes). Reach for it on every refreshable root surface; do not hand-roll the eyebrow swap or the trigger haptic at call sites.

### Deadline family: usage and division of labour

**Library's grid/cover-only cells use a distinct countdown badge** (a Library-local composable, not the shared `Badge`/`CoverOverlay`/`DeadlineSummaryLine` family below): top-**start**, `primary`/`onPrimary` fill (`errorContainer`/`onErrorContainer` while behind schedule — a deliberate deviation from the redesign spec's single-primary badge, kept because the app already reserves error for "needs attention" everywhere else), a calendar glyph (`SoftcoverIcon.DateRange`) + "N days" (a duration, not a date — "Aug 28" reads like a release date, "9 days" reads as time remaining), reading "Expired" once the deadline has passed. It is the reason Library's state still carries a domain-typed `deadlineProgressByBook` beside its badge and summary models. The two badges are not swapped project-wide: Reading and Book detail keep the top-end status-label `Badge` (`OnTrack`/`Behind`/`Expired`) unchanged; only Library's grid cells use the countdown.

**Division of labour across the family:** the badge (either kind) carries status, the `DeadlineSummaryLine` carries the date + the per-day pace still needed to make it, and Book detail's `DeadlineRow` is the only surface that additionally spells out how far behind schedule the reader is. A surface that shows a badge and a summary line together is not duplicating itself — that pairing is the intended full readout, and it is what Library's List (large) row, the Reading hero, and the Reading secondary row all use. **Give the summary line the full width of its row.** It is single-line by contract, and its width is not something a caller can predict: the date is whatever the reader's own `DateStyle` renders, the pace is unbounded (a two-day deadline on a thousand-page book reads "1149 pages/day"), and both grow with the system font scale. Put inside a weighted text column that also holds a cover and a trailing control, it wraps — which also drags the calendar glyph out of alignment, since it centres against the resulting two-line block. So a row renders it *beneath* its content rather than inside the column (see the Library row and Reading secondary row patterns in §5); the component's own `maxLines = 1` is the backstop for extreme font scales, not the layout plan. Do not "fix" a wrap by measuring the container or branching on window size — the fix is always to give the line the width.

### Unreleased badge

The canonical mark for a book whose effective release date is in the future. It is not its own component: it is `Badge` (`core:component`, `badge/`) carrying `BadgeTone.Release` (`primary`/`onPrimary`, so the chip reads as a deliberate publishing signal rather than another deadline state). The copy and the metrics are resolved by `LocalDate.toUnreleasedBadgeUiModel(style)` in `core:uibinding`, `release/`, from a three-entry `UnreleasedBadgeStyle`:

- **`Compact`** — "Out MMM d", with the year appended only when it is not the current year. Sits as a top-start overlay on cover art in carousels and grid cards, including Explore's Up-next lead card once it isn't yet released, which names its date the same way every other unreleased rail card does rather than a generic "Coming soon".
- **`Prominent`** — "Releases MMMM d, yyyy", inline beneath the hero byline on book detail. When it is shown, suppress the trailing release year in the byline so the date isn't named twice.
- **`Featured`** — "Arriving MMM d", Explore's unreleased featured hero, and the only user of `BadgeVariant.FeaturedRelease`'s larger pad.

The style enum deliberately stops at the mapper and never reaches the component (§7 R11): it picks copy and placement, which resolve into a label and a variant on the model. The "is it unreleased?" check is centralised on `Book.isUnreleased` — never compare dates at the call site, and never in composition. Note one deliberate asymmetry: Explore's featured hero badges on `effectiveReleaseDate` alone without consulting `isUnreleased`, because that card is by construction the upcoming-release hero.

### Search results pagination

Explore's search-results list/grid (feature-owned) has no server-side total (the search endpoint returns no hit count), so paging is a "maybe more" append: a `LaunchedEffect` + `snapshotFlow` over the list/grid state's `layoutInfo.visibleItemsInfo.lastOrNull()?.index` dispatches the "load next page" action once the visible window comes within a fixed item-count threshold of the fetched end, gated on a `hasMore` flag from state. A tail `CircularWavyProgressIndicator` (full-width row on mobile's `LazyColumn`, a `GridItemSpan(maxLineSpan)` row on desktop's `LazyVerticalGrid`) shows while the append fetch is in flight and disappears once `hasMore` goes false. There is deliberately **no "N of M" count** anywhere in this surface — only the append spinner and its disappearance communicate paging state.

### Connectivity chrome

The offline report is two components plus one state read, deliberately split across two modules. `Banner` + `offlineBannerUiModel(visible)` (the transient "you're offline" strip the app shell raises in `RootScreen`) and `EmptyState` + `offlineEmptyStateUiModel()` (the full-surface placeholder for a screen whose content cannot load offline) are **`core:component` components** — see their own entries below. `rememberIsOnline()` lives in **`core:presentation`** (`connectivity/`), because reading network availability means resolving a provider out of DI and the component library may not reach for DI (§7.4); it is consumed by the shell and by any feature screen that must degrade offline (`explore`, `book_detail`). Reach for `EmptyState` with the offline model for any "needs the network" empty state; do not hand-roll a per-screen offline placeholder.

### Update highlight card

The Settings screen's `primaryContainer` editorial highlight (`AppUpdateSection`), shown only while an app update is not `Idle`. This is a **second, distinct tinted-card convention from the primary-filled hero stat card** (§2.1): where the hero stat fills solid `primary` and is capped at one per scrollable region, this card fills `primaryContainer` / `onPrimaryContainer` (radius 12dp) and is reserved for this one system-status callout. Anatomy: a hand-composed accent-bar + all-caps Inter eyebrow (not `EditorialSectionHeader`, since its headline is fixed to `onSurface` and this card needs `onPrimaryContainer`), an italic Fraunces headline, and a state body — a fully-rounded `Surface(onClick, shape = percent(50))` pill action (`primary` / `onPrimary`, the same anatomy as `Chip` and the Library control-line pills) for Available/Downloaded/Failed, or an **indeterminate** `LinearWavyProgressIndicator` (`primary` stroke / `outlineVariant` track, no percentage) while Downloading — the client has no reliable version string or download percentage to show, so headlines and copy are deliberately version-less ("A new version is ready", never "Version 3.2.0"). No badge, no chevron, no whole-card click — the pill (or the absence of one, while downloading) is the only affordance.

### Banner

`Banner(model: BannerUiModel)` (`core:component`, `callout/`) is the full-width line of chrome that slides in above a screen's content to report a condition the reader should know about. It owns its own expand/shrink transition, so a caller flips `BannerUiModel.visible` rather than wrapping it in an `AnimatedVisibility` of its own. Its `tone` is a *meaning* resolved onto the theme's container roles, never a colour the caller picks; `WARNING` (the `errorContainer` pair) is the only one so far. The **offline notice** is its one instance: the copy belongs to the component rather than to a feature — every surface that reports being offline reports it identically — so the library owns the string and `offlineBannerUiModel(visible)` resolves it. It is raised once at the app root (`RootScreen`), never per screen; the connection itself is read through `rememberIsOnline()` in `core:presentation`, because resolving that provider is DI and the library may not reach for it (§7.4).

### Empty state

`EmptyState(model: EmptyStateUiModel)` (`core:component`, `state/`) is the centred headline-and-body message a screen shows in place of content it has nothing to draw. It fills and centres within whatever space its `modifier` gives it — the whole screen, a pane, a sheet body — so the caller decides the footprint and the component decides the composition. The **offline screen** is its first instance, via `offlineEmptyStateUiModel()`, on the same library-owns-the-copy reasoning as the banner above; Book detail and Explore both swap their body for it when `rememberIsOnline()` is false. The app's remaining per-screen empty states consolidate onto it.

### Mark-as-read celebration

`MarkAsReadBurst(model: MarkAsReadBurstUiModel)` (`core:component`, `celebration/`) is the canonical hero moment for a successful mark-as-read commit. It paints a radial particle burst (primary + tertiary tinted) outward from the centre of its footprint; replays whenever the model's `triggerKey` changes to a new non-zero value; suppressed under reduced-motion (§2.5). Particle count and duration ride on the model (the reading screen celebrates bigger and slower at full-screen scale). The two tints are still loose `color` / `secondaryColor` parameters — an R11 holdout scheduled for the contract retrofit, since a tint is exactly the kind of treatment two surfaces silently drift apart on. Compose it as a sibling overlay (`Modifier.matchParentSize()` or `Modifier.fillMaxSize()`) on whichever surface owns the commit — the shelf-action card on book detail and the reading screen at full-screen scale. Always pair the trigger with a single *commit* haptic so the visual and haptic land together. Do not reach for it on other status transitions — read is the only shelf change that earns a celebration.

### Deadline badge / cover overlay / summary line

The family of components that mark a book as time-bound, all three in `core:component`, `badge/`. Used together when a book's deadline matters; never mixed with a stale rating row in the same card. Each takes a UI model and nothing else (§7 R11), and the model is built in the feature's collector, never in composition (R9/R10): the render looks its model up by book id and forwards it.

- **`Badge(model: BadgeUiModel)`** — one label on a rounded `6dp` surface. `BadgeTone` carries the meaning: `OnTrack` (`primaryContainer`), `Behind` (`errorContainer`), `Expired` (`surfaceVariant`), and `Release` (`primary`) for the unreleased badge above. `BadgeVariant` carries the metrics through `BadgeDimensions.forVariant` — `Standard` is the `6dp`/`2dp` pad every badge uses, `FeaturedRelease` the `8dp`/`4dp` pad Explore's unreleased hero has always used. Two entries rather than one because tuning one surface must not move the other.
- **`CoverOverlay(model: CoverOverlayUiModel?, content:)`** — wraps cover art with a top-**end** status badge and desaturates the art once the deadline has expired (`grayscale`). The model is **nullable**, like `Cover`'s, because it arrives one state emission after the book it decorates; a null model renders the content alone.
- **`DeadlineSummaryLine(model: DeadlineSummaryUiModel)`** — the date paired with the pace still needed to make it ("28 Aug • 18 pages/day"), or the status label alone once expired. `DeadlineSummaryTone` picks the ink: `OnSurface` (`onSurfaceVariant`) everywhere, `OnHeroBackdrop` for the one case that sits on an image rather than a flat surface — the Reading hero's blurred-cover backdrop. It is a **tone, not a `Color` parameter**, because the default ink is a theme lookup that only resolves in composition and so cannot be a field on a model built in a collector.
