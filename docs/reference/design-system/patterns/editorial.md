# Patterns — Editorial

### Editorial section

Accent bar (optional) → eyebrow → display headline → body (carousel, list, or block). The default way to introduce any region.

### Hero stat

A single oversize number in `statHero` or `statLarge`, an editorial suffix beneath in italic body, on-surface-variant. Used for "books read this year", "pages today", and progress sheets. The unit (e.g. "pages", "books") is named in the eyebrow above the number, never trailed next to it — pairing a unit suffix with the oversize numeral fights for horizontal space and breaks once the number grows. The number itself uses single-line autosize down from `statHero` so power-reader counts (six- or seven-digit page totals) still fit the card without reflowing the layout. The numeral is rendered via `StatNumber` (components.md) so changes tween in place — raw `Text` for a live-bound stat is a bug.

### Editable hero stat

Same as hero stat, but the number is editable — rendered through the shared `HeroStatNumberField` component (components.md): a borderless `BasicTextField` styled with `statLarge`, cursor in primary colour, width computed from character count so the field does not jump as digits are typed. Pair it with an `EditorialSuffix` caption ("of 195 pages", "of the way through"). Used by the Update progress sheet and Focus Mode; do not hand-roll a boxed field for an editable hero number.

### Editorial quote

Oversized low-alpha `quoteGlyph` (tinted `onSurfaceVariant`) behind an italic headline-medium pull quote, with a primary-coloured byline beneath. Surfaces notes, reviews, or a featured passage. The same glyph treatment also serves as a decorative flourish in empty states (e.g. "no books currently reading"): the empty-state variant swaps in an italic encouragement headline where the quote text would sit, and drops the byline. In empty states only, the glyph plays a slow infinite ±2° sway (~6.8s each direction, FastOutSlowIn) via `Modifier.quoteGlyphSway()` — a magazine pull-quote breathing, never a marquee. Do not apply the sway to populated quote cards (review cards, share cards) — content next to the glyph fights a moving mark for attention. Suppressed under reduced motion (§2.5 gate).

### Standfirst

A book's `headline` — a one- or two-line editorial introduction owned by the book itself (not the edition) — rendered as a magazine *standfirst* (the bold lead between a title and its body). It opens the book-detail **about section**: directly under the `About` `SectionLabel`, set in the editorial `bodyLarge` role (italic Fraunces, `onSurface`) so it reads as a subtitle/lead rather than a competing headline, with a gap (≈16dp) before the drop-cap description body begins. It sits in the editorial italic voice deliberately — a roman title/`titleMedium` register would read as structural chrome, and a `headline`-scale role oversizes a one-sentence intro into three wrapped lines. The title lives in the cover hero above, so the standfirst is the page's first on-`surface` editorial voice and leads the eye straight into the description — title → standfirst → body, the classic spread rhythm. It is plain text, never run through `htmlToAnnotatedString` (that path is for the server-HTML description below it). Suppressed when the book has no headline; when a headline exists but the description is empty, the standfirst stands alone and the "No description…" fallback is omitted. Reach for it wherever a record carries a short curated lead distinct from its long body; do not promote it to its own section header or reuse the section-headline `display` role (that would compete with the section eyebrow).

### Prose toggle

A sentence rendered as normal running prose where one or two words are themselves the control — tapping a word selects it, in place, with no separate widget beside the sentence. Anatomy: the chosen word renders in `primary`, a heavier weight, and a thin (2dp) `primary` underline; every other candidate word renders demoted (`onSurfaceVariant` at reduced alpha) with a **transparent** underline of the same thickness reserved beneath it, so choosing a different word never reflows the sentence. Each word's own tap target is expanded via `Modifier.minimumInteractiveComponentSize()` rather than by enlarging the glyph, so a short word stays typographically correct while still meeting the 48dp minimum. Reach for this instead of a `Switch` or segmented control when the setting is genuinely binary, reads naturally as a sentence, and does not need a caption to explain itself — the sentence already says what it means (the create-list sheet's "This shelf is *public* / *private*." is the reference use). It is currently feature-local to create-list (`feature/lists`); promote it to `core/component/` (behind a UI model, per §7) once a second surface needs the same "sentence you tap to flip" control.

### Rendered markdown document

A flat, source-order block list (heading / paragraph / bullet or ordered list item / blockquote / thematic break, each carrying independently-flagged bold/italic/code/link inline runs — never a nested mark tree) rendered as an editorial spread rather than raw markdown. A release-shaped heading (`"3.2.0: Title"`, splitting on the first `": "`) becomes an eyebrow + headline through `EditorialSectionHeader`; a heading without that shape degrades to a plain headline, since the header always needs both. Consecutive bullet/ordered items are grouped by the renderer into one run (the parser emits them as flat top-level blocks, not a nested list container) and rendered as a single `Text`/`AnnotatedString` per item with a hanging `TextIndent`, so a wrapped continuation line aligns under the item's own text rather than under the marker. A thematic break is a hairline `HorizontalDivider`, never a raw `---`. A blockquote is a quiet accent-bar aside (a thin `outlineVariant` bar beside italic `onSurfaceVariant` text), not a boxed card. Long-form paragraphs and list items read in the non-italic `review` role (built for extended reading, unlike the shorter italic `body`/`bodySmall` captions elsewhere) so a whole document stays comfortable at length; a blockquote aside keeps the italic `body` role since it is a short interruption, not the page's main text. Every inline run with a link renders through the shared `ClickableText` (`core:component`, `richtext/`) with a `"url"`-tagged string annotation, so taps resolve without a `Row` of `Text`s breaking the paragraph's wrap. Used by the Settings → About → Roadmap screen (`feature/settings`, rendering the repo's public `ROADMAP.md`); reach for it again for the next markdown-shaped document a screen needs to render rather than hand-rolling a second block renderer.
