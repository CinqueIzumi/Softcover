# Patterns — Library

### Masthead-as-shelf-switcher (Library, mobile)

Four rows of chrome (eyebrow, pill tab row, search toggle, sort/filter/layout strip) collapse to two: the page title *is* the shelf switcher. Anatomy, top to bottom, inside the page's collapsible header block: eyebrow (`PullToRefreshEyebrow`, unchanged) → a **title row** pairing the shelf name (`pageTitle`, autosized down via `TextAutoSize.StepBased` for a long name, clamped to 3 lines) with a trailing primary chevron-down (24dp, top-aligned) → the stat subtitle (`body`, `onSurfaceVariant`, unchanged `subtitleFor` copy). The whole title row is one tap target (`pressScaleClickable`) that opens the **Shelves sheet** below — the explicit, jump-anywhere switcher. Adjacent shelves are *additionally* reachable by swipe: a `HorizontalPager` backs the content area, one page per `visibleTabs` entry, gated on the **"Swipe between shelves"** preference (Settings → Appearance → Display, **opt-in, default off**; absent on desktop) — so this masthead-only anatomy is what a reader sees until they ask for the gesture. The header block follows `pagerState.currentPage`, so title, stat subtitle, control line, filter chips and the neighbour rail all change over at the **halfway point** of a drag, while the tab-select action fires only on `settledPage` — a cancelled swipe therefore writes nothing to state. Sheet-driven selection snaps the pager across with `scrollToPage` (instant, since the sheet is dismissing over it); the neighbour rail's taps use `animateScrollToPage` instead, because a deliberate one-shelf move should show the slide. Swiping is suppressed in **selection** mode (a selection is anchored to the shelf it was made on) and in **rearrange** mode (a page swipe would fight the reorderable grid's drag). Below the (still scroll-collapsible) title block sits the **persistent** `EditorialSearchField` (components.md, no toggle), then the **control line** (below), then the **shelf neighbour rail** (below). **Desktop keeps its permanent shelf sidebar as the switcher instead** (§2.7 expanded-width source-list pattern) — no title chevron, no Shelves sheet there; the sidebar already gives a wide window a switcher. Persistent search and the control line are shared by both platforms.

### Masthead control line

One row, both platforms, sitting directly beneath the persistent search field. **Left:** the current sort mode's label (`eyebrowSmall`, `onSurfaceVariant`, uppercase) plus a 16dp primary asc/desc chevron — hidden under a positional sort (Manual/Order, where the stored order *is* the sort, so a direction arrow is meaningless) — tapping either opens the **Arrange sheet** (below). Immediately beside it, an inline **"Reorder"/"Done" hint chip** (drag-handle glyph + label, `surfaceContainer`/`onSurfaceVariant` idle, `secondaryContainer`/`onSecondaryContainer` while engaged) appears only when the current tab is on a reorderable positional sort with ≥2 visible items — see "Rearrange mode" (patterns/library-editing.md). **Right:** a `surfaceContainer` **Filter pill** (17dp filter glyph + "Filter" label, `inversePrimary` dot when a filter is active) opening the Filter sheet, and a 38dp `surfaceContainer` **Select circle** (checkbox glyph) that enters selection mode with an **empty** selection — unlike a cover long-press, which seeds the pressed cover, the toolbar has no single book to anchor to, so it opens empty and the user picks their own start (`OnEnterSelectionModeAction`'s `bookId` is nullable for exactly this: `null` from the Select circle, the pressed cover's id from a long-press). The Select circle is omitted on custom-list tabs (editions don't carry shelf-selection semantics) and on an empty shelf. There is **no layout affordance on the control line at all** — layout lives inside the Arrange sheet alongside sort. 24dp horizontal page gutter; hides during bulk-select mode (selection has its own header) with the same `expandVertically`/`shrinkVertically` register the chip rows use.

### Shelf neighbour rail (Library, mobile)

Shown because the swipe gesture needs it: without this rail nothing on screen says which shelf is next door, so a swipe would be blind. It sits directly beneath the control line (and beneath the active-filter chip row when that shows), immediately above the grid. Anatomy: a `HorizontalDivider` (`outlineVariant`) above and below a **fixed-height 48dp** row, 16dp page gutter, one end per neighbour — leading chevron + previous shelf name at the start, next shelf name + trailing chevron at the end, both in `eyebrowSmall` **uppercased**, `onSurfaceVariant`, clamped to 1 line with `TextOverflow.Ellipsis` so a long custom-list name truncates instead of shoving the other end off screen. Each **half of the row** is a tap target (`pressScaleClickable` + `pointerHandCursor`, no haptic — this is navigation, not a commit) that animates one shelf across: the label sits at its own edge but the whole weighted half takes the tap, because a caption plus a 16dp chevron is too small a thing to aim at. The row is 48dp rather than the ~36dp the labels need for exactly that reason — the minimum touch target sets the band height, not the type. On the first or last shelf the missing end renders as an **empty weighted slot**, never a shifted layout: the row keeps its height and the surviving label stays anchored to its own edge, so reaching either end of the shelf order never nudges the grid. Shown only when the swipe preference is on, there is more than one visible shelf, and the user is neither selecting nor rearranging (in both of those the pager is frozen, and a rail would promise a gesture that mode does not accept). Desktop has neither the rail nor the pager — its permanent sidebar already names every shelf at once.

### Shelves sheet (Library, mobile)

Opened by tapping the masthead title (above); the sheet form of the shelf switcher. Canonical editorial header (accent bar + `YOUR SHELVES` eyebrow + headline), with a quiet trailing "Manage" text affordance in the header row that routes to the shelf-visibility settings screen. Below the header, one hairline-split row per `LibraryUiState.visibleTabs`: a leading glyph (a shelf icon, `onSurfaceVariant`, for the built-in All/status shelves; a list icon, `primary`, for custom lists — built-in shelves and custom lists render as *equals*, distinguished only by this glyph), the shelf name (`titleLarge` forced italic, clamp 2 lines, `primary` when it's the active shelf), a trailing tabular item count (`tabStatsFor`), and a check glyph on the active row. Tapping a row dispatches the tab-select action and dismisses. Desktop never shows this sheet (its sidebar is always visible).

### Arrange sheet

One sheet, shared by mobile and desktop (opened from the masthead control line above, or the desktop equivalent), covering both sort and layout. Canonical editorial header (`ARRANGE THE SHELF`), then two sections: **LAYOUT** — three fully-rounded chips (Grid·2 / Grid·3 / List; active `primary`/`onPrimary`, idle `surfaceContainer`/`onSurface`) that are a pure UI bucketing over the existing persisted grid-layout enum (no new persisted field), followed by a "Show titles & authors" `Switch` row (Fraunces italic label) that's hidden on the List chip and otherwise flips the enum's titled/cover-only sibling — and **SORT BY · {shelf name}** — the shelf's gated, ordered sort-mode list as chips (same anatomy as the layout chips); tapping the already-active chip flips its direction (a trailing chevron on the active chip signals which way, suppressed for Manual/Order). **Draft/commit:** layout, titled-ness, and sort mode/direction are a local draft — seeded from the committed grid layout / sort mode / direction the moment the sheet opens — that every chip tap and the titles toggle mutate in place; nothing reaches state until the footer button fires `OnApplyArrangeAction`, which commits all three atomically, and dismissing any other way (scrim, back) discards the draft untouched. The one exception is **"✶ Make this list ordered"**, which appears beneath an unranked custom list's chips and stays live/immediate on tap (`OnSetListRankedAction`) since it flips a structural list flag rather than a sort/layout preference — the draft's sort mode is nudged to `ORDER` right after so the chip row doesn't look stale for the rest of the visit. A full-width filled `RhaydusButton` footer ("Show N titles", previewing the *already-committed* count — sort/layout never change how many titles show) commits-and-dismisses, sized `ButtonSize.M` on **both** sheet and panel forms — not the L-on-sheet/M-on-panel split the Update-progress sheet uses, since L reads too tall for this footer on either form. Desktop's grid still renders at an adaptive column count regardless of the Grid·2-vs-3 chip choice (§3.6 large-window list/grid rule) — the chip only round-trips the enum value, which the desktop grid maps by titled-vs-cover-only and grid-vs-list, not by literal column count.

### Filter sheet

The facet picker (canonical header, `FILTER THIS SHELF`): a merged **Ownership · Format** section, **Release year**, **Year finished** (Read tab only, from `LibraryFilterOptions.readYears`), a **Tags** section, then **Rating** — each a `FacetSection` of `Chip`s, wrapping (`ExpandableFlowRow`) on the panel form and horizontally scrolling on the sheet form (§3.5). The Tags section additionally carries a trailing count reading **"N available"** — the number of distinct tags the shelf's books carry, *not* how many the user has selected (which would read wrong at "1 in use" with a dozen more to browse) — and a search-your-tags pill that narrows the chip cloud by substring, client-side, as transient local state (not part of the TOAD contract). That pill is a hand-composed leading-icon + `BasicTextField` pill rather than the foundation `EditorialSearchField`: that component hardcodes its own 24dp horizontal padding and a ~56dp height meant to sit directly on a page, which — nested inside this sheet's already-24dp-padded facet column — would both double-inset the pill past the other facets' left edge and blow past the sheet's tighter search-pill height. **Draft/commit:** every facet chip and the in-sheet "Clear all" mutate a local `LibraryFilters` draft, seeded from the tab's committed filters the moment the sheet opens; the footer's "Show N titles" count previews *that draft* live (plus the current search) via `libraryPreviewCount`, so it always matches what committing would actually show. Nothing reaches state until "Show N titles" fires `OnApplyFiltersAction` with the whole draft and dismisses; dismissing any other way (scrim, back) discards the draft untouched. This is deliberately separate from the main-screen active-filter chip row, which stays live/immediate (`OnToggleFilterValueAction` / `OnClearFiltersAction`) since it has no commit step of its own. The footer: a full-width `ButtonSize.M` "Show N titles" button, beside an **always-rendered** "Clear all" text affordance (clearing the draft, not dispatching) that dims to ~0.4 alpha and goes fully inert — no click handler, no desktop hand cursor — when the draft has no active filter, rather than appearing/disappearing, so applying the first filter never shoves the primary button sideways.

### Library layout model

The three Arrange-sheet layout chips (Grid·2 / Grid·3 / List) and "Show titles & authors" toggle are pure UI mappings over Library's existing six-value grid-layout enum — no persisted-model change. "Show titles" reflects whether the current layout is a titled grid or its cover-only sibling; toggling it flips between the two, preserving the Grid·2-vs-3 choice. Picking a layout chip preserves whichever titled-ness was already set. The List chip always resolves to the large (de-carded) row layout; the enum's older compact-list value is **not offered** by the picker — it is kept only so a value an older client persisted still renders (as the large-row layout, not a blank fallback), not as an option a user can newly choose.

### Library cover grid and de-carded list row

The grid/cover-only cells (§3.4-style anatomy, unchanged cover-then-caption order) add two rows around the cover, both height-reserved so a shelf mixing in-progress and untouched books never jumps: a countdown deadline badge overlaid top-start on the cover itself (only while the book has a tracked deadline — see the Deadline badge entry in components.md), and a thin `LinearWavyProgressIndicator` line immediately beneath the cover (`primary` indicator, `outlineVariant` track, 8dp reserved height) while the book is in progress — reading Library's specific instance of the app-wide "progress is always wavy" rule (§6). The List (large) row is **de-carded**: a hairline `outlineVariant` top divider and `18dp` vertical row padding stand in for a boxed card, matching the flattened anatomy the rest of the shelf reads with (masthead, control line, chip row — no boxed regions). Byline reads `BY {AUTHOR}` in `eyebrowSmall` (uppercase, `onSurfaceVariant`) rather than the plain sentence-case "By {author}" other surfaces use. In progress, the same wavy line (120dp wide) sits beneath the meta line with a tabular `NN%` beside it; the row shows **no** deadline badge (the wave already carries reading state) but does carry the `DeadlineSummaryLine` — date + the per-day pace still needed — whenever the book has a tracked deadline. That line sits **beneath the whole row**, as a sibling of the cover/text/trailing `Row` rather than another entry in the weighted text column, so it gets the row's full width (the row's `18dp` vertical padding moves onto the wrapping `Column` that now holds both) — its width can't be predicted from the caller (see the Deadline summary line entry in components.md), so it needs the row's full width rather than a column it may wrap inside. The line is needed because neither the countdown badge nor the wave names the date or the pace. Library's other layouts are unchanged: the grid/cover-only cells carry the countdown badge alone and the List (compact) row the status `DeadlineBadge` alone, both too narrow for the line. **This byline treatment also applies beyond Library:** the Hidden Suggestions screen's hairline book row (a "Settings menu row"-style anatomy, components/navigation.md) reuses the same `BY {AUTHOR}` `eyebrowSmall` byline, since that row sits in the same flat, hairline-separated register this one does and a full sentence read as too heavy beside the compact cover. Reach for it on any other hairline-row book listing in this same flattened register; a boxed-card or carousel row should keep the plain sentence-case byline.
