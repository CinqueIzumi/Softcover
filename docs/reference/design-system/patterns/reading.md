# Patterns — Reading

### Backdate a logged action

A sheet that logs something happening *now* (the Update progress sheet's page/percentage/time tabs) may let the reader say it actually happened earlier, defaulting to "Just now" (no backdate — the mutation carries no explicit timestamp and the server stamps its own current time). The affordance is a single icon-leading pill (`surfaceContainerHigh` idle, swapping to `secondaryContainer` once customised, `SoftcoverIcon.DateRange` leading glyph) sitting once in the sheet's shared chrome — above whichever unit tab is active, not duplicated per tab — so every tab's submit carries the same picked moment (literally: each submit member of `ProgressSheetEvent` carries its own `actionAt`, rather than the sheet holding one for the host to read). Tapping it seeds the picker with the current instant and expands an inline day + time-of-day editor beneath the pill (`AnimatedVisibility` + `expandVertically`/`shrinkVertically`); a trailing clear glyph resets to "Just now" and collapses. The editor reuses the sheet's existing `StepperCircle` (see "Editable hero stat", editorial.md, for the stepper anatomy) for both the day ("Today" / "Yesterday" / "N days ago") and the time-of-day (hour ±1h, minute ±15m) controls — every step shifts the picked instant by a fixed duration and clamps it to "now", so a reader can never dial in a future moment; a stepper simply stops moving once it reaches that boundary rather than throwing an error. Used by the Update progress sheet's `WhenReadRow`; reach for the same pill-plus-inline-stepper-editor shape for any future "log this in the past" affordance rather than reaching for a platform date/time picker dialog, which reads as system chrome against the editorial register.

### Reading-session peek bar

While a reading session is running, a persistent live-timer bar (`SessionPeekBar`, components.md) sits directly above the bottom navigation — between the tab content and the nav, in both the docked and floating bar styles — and slides in when a session starts, out when it ends. It is the always-glanceable in-app counterpart to the lock-screen notification — a **plain, persistent ongoing notification** (`BigPictureStyle` edition cover, running chronometer, pause/resume + stop + an inline "update page" reply), hosted by `ReadingSessionService` as a foreground service and kept persistent — since Android 14 ignores `setOngoing` for FGS notifications, a `deleteIntent` re-posts it if the user swipes it away, so it returns and is removed only when the session ends. <!-- history-ok -->It is deliberately **not** a media/`MediaSession` notification: that was tried and abandoned because a real audio app (Spotify) wins the single media slot and overwrites it, and because a media session drags in the speaker-output chip and media-button capture. A plain notification always shows independently, touches no audio routing, and never competes for media controls. All three surfaces (peek bar, lock screen, Focus Mode) read and drive the one app-scoped `ActiveSessionController`: same book, same running timer, same pause/resume + stop controls. Tapping it opens Focus Mode. Mount it once at the app shell; never reserve layout space for it when idle (it animates from zero height), and never let a screen render its own session timer — if a surface needs to show "you're reading this now", it reads the controller.

### Focus Mode

A distraction-free full-screen reading surface for the active session, pushed over the bottom-bar shell (so the peek bar and nav recede). It is an **editorial hero on the page `surface`** (§3.3), not a dark scrim — a centred column reading top-to-bottom: a `NOW READING` eyebrow (primary), the book cover (subtle radius + shadow, §2.3), the title in `display` (italic, on-surface) over a `By …` byline in `body` (on-surface-variant), then the running timer as a **hero stat** (editorial.md) — an eyebrow label (`READING TIME`, or `PAUSED` in on-surface-variant) above the `statHero` numeral (a formatted `H:MM:SS` string driven by a one-second `LaunchedEffect`, dimmed to on-surface-variant while paused; `StatNumber` is for live integers, not a composite time string, so it does not apply here). Below sits the editable page as an **editable hero stat** (`HeroStatNumberField` + `EditorialSuffix` "of N pages" + a progress bar — the same treatment as the progress sheet's page tab; it commits the new page on focus loss through the same `RecordBookProgressUseCase` the reading screen uses, and falls back to a read-only "% complete" for books without a page count), then a pause/resume (`FILLED`) + stop (`OUTLINED`) `RhaydusButton` row. All copy uses editorial roles on the page surface so it stays legible — never dark-on-dark. It owns no domain state beyond a transient page-input buffer, so it reads `ActiveSessionController` directly rather than carrying a TOAD ScreenModel, and pops itself the instant no session is active. Reached three ways — the peek-bar tap, the featured-card "Focus mode" button, and the lock-screen notification's content tap (deep-linked through a `singleTop` `MainActivity` into a consumable focus-mode flag the root observes). Reach for this register when a session wants the whole screen; do not build a second full-screen timer.

### Streak strip

A compact 21-day reading-activity row sitting in the Reading screen header, directly below the greeting subtitle. Days run **most-recent-first** — today at the left edge, older days trailing right — inside a **horizontally scrolling** `Row` (`Modifier.horizontalScroll`, fixed dot size + `spacedBy` gap) so every dot stays comfortably sized rather than cramming 21 into the viewport and clipping the recent end on narrow phones. A **lit** day (the user read anything that day) is a filled `primary` dot; an **unread** day is a faint track dot (`onSurfaceVariant` at ~0.18 alpha); **today** is a slightly larger dot (filled `primary` when read, or a `primary`-ringed track dot when not) anchored at the scroll origin so it reads as the home position. Orientation is carried by a **static, direction-only caption** beneath the dots ("Most recent first", `eyebrowSmall`/`onSurfaceVariant`), right-aligned beside an italic Fraunces `bodySmall`/`primary` **"N days running"** caption — the current streak length, computed as a pure UI-layer helper counting consecutive read days backward from today through the same activity list the dots render (no new domain concept). The caption is omitted (not space-reserved) whenever today itself was missed, since "0 days running" reads as a non-sequitur; the dots-only caption alone still carries the row's orientation in that case. The date label is deliberately *not* a per-end date, since a scrolling row would make any pinned "Today / 10 May" end-marker drift out of sync with the dot it names. The dot is **binary** — it reflects *that day's own* reading activity, fully decoupled from the current streak run (a gap day simply goes dark while earlier read days stay lit). "Read anything" is sourced from the same Hardcover reading-journal dates the Profile streak uses — never from optional reading sessions, which users may not run. The whole row is one `pressScaleClickable` tap target that fires `Haptics.select()` (§2.5) and opens a transient per-day breakdown `AdaptiveModalSheet` that — like every sheet (§3.5) — opens with `EditorialSectionHeader` (a "Last N days" eyebrow + a "you read N of the last 21 days" headline), then one row per day, most-recent first, each with its dot and a relative `Today`/`Yesterday`/`EEE d MMM` label. It is the interim affordance until the full Reading Activity calendar lands. The strip carries a fixed dot-cell height so dots filling in never reflow it; when no day in the window has activity it is **omitted entirely** (not space-reserved) so a new user never sees a row of dead dots — accept the one-time header grow when the first day is logged. Reach for this pattern when a header needs an at-a-glance binary activity history; do not overload the dot with duration/intensity tiers (that is the calendar's job).

### Reading featured-hero card

The Reading screen's emotional centre: a `surfaceContainerLow`, 22dp-radius card with its overflow clipped, holding (top→bottom) an optional pace-nudge ribbon fused to the card's own top edge and, beneath it, **one continuous blurred-cover backdrop spanning the entire rest of the card** — cover, meta, the page-count/percentage stat, the wavy bar, the deadline row, both pills, and the caption all sit over the same image, never a backdrop band handed off to a separate flat body surface. **Backdrop:** a full-opacity blurred cover image (blur 64dp), a `Color.Black` top scrim fading out by ~55% down the card (legibility for the series eyebrow near the top edge), and a fade at the foot into the card's own `surfaceContainerLow` — no fixed-ink field, no radial glow, no left→right scrim. Over the backdrop, one content column: the featured cover (108×162, 4dp radius, `DeadlineCoverOverlay`, no cover-edge ornament) beside a text column — a series eyebrow (or the mutation-failed retry line, in `error`, when a save failed), the hero title (`headlineSmall`, italic), the byline, and — only when the collector has a computed forecast for this book — a "Your pace" label-and-rule row over an italic pace line ("35 pages a day — about 5 days to go") — then, below that row, a page-count line (current at full alpha, "of N" demoted to 0.6 alpha) beside the "NN%" stat (`headlineSmall`), an M3-expressive `LinearWavyProgressIndicator` (never flat — §6), an optional `DeadlineSummaryLine` (calendar glyph + the deadline date and the per-day pace still needed to make it — the status word is not repeated here because the cover's `DeadlineCoverOverlay` badge right above already carries it; passed the fixed `ReadingHeroBackdropForeground` ink via the component's `foreground` parameter, since it sits on the backdrop image), a filled "Update progress" pill (`primary`/`onPrimary`, unaffected by the backdrop since a filled button carries its own solid fill), the session button (outlined "Start reading session", or tonal "Focus mode" while a session on this book is active — the one place a hero action legitimately swaps style based on live state), and an italic time-of-day caption. **Every one of those lines — meta text, page count, percentage stat, deadline row, caption — is set in the fixed `ReadingHeroBackdropForeground` ink (§2.1)**, not `onSurface`/`onSurfaceVariant`, because the whole column sits on the image rather than a flat card surface. The outlined session pill is the one catalog component that can't take a colour parameter for this: `RhaydusButton`'s `OUTLINED` style hardcodes its border and label to the theme's `outline`/`onSurface` roles, so the idle "Start reading session" state wraps it in a scoped `MaterialTheme(colorScheme = MaterialTheme.colorScheme.copy(outline = …, onSurface = …))` override (shapes/typography still inherited) so the border stays visible against the image regardless of theme — the filled pill and the active-session tonal pill need no such override, since both carry their own solid fill. There is no split-button/dropdown here — mark-as-read lives only in the Update-progress sheet, whose "Mark as read" action Reading wires to the same commit choreography a book's row/hero mark-as-read affordance always uses (haptic, burst, bottom-bar pulse, and the slide-to-shelf follow-through when motion is enabled, §2.5). Reach for this anatomy only for Reading's single featured book; do not reuse the backdrop treatment for a general "hero card" without updating this entry.

### Reading secondary row

The "also reading" rows beneath the featured card: a flat, hairline-`outlineVariant`-topped row (drawn on every row including the first, so a run reads as one continuous list — the same idea as the Settings menu row's hairline, components/navigation.md) rather than its own card, 24dp horizontal / 18dp vertical padding. Anatomy: a 54dp cover, a text column (series/mutation-failed line, `titleMedium` title — Roman, not italic; a list-item title stays on the app's Roman convention for card/list titles, §2.2, even though the redline mockup sets it in italic — the italic reading is reserved for headline/body/stat roles), author, and a slim wavy progress line (`LinearWavyProgressIndicator`, `weight(1f)`) with a trailing `NN%`. When a deadline is tracked, a `DeadlineSummaryLine` (calendar + date + per-day pace, the same readout as the hero; status is carried by the row's own cover badge) sits **beneath the whole row** — a sibling of the cover/text/chip `Row` inside a wrapping `Column` that now owns the row's `24dp`/`18dp` padding — rather than as another line in the text column, since that line's width can't be predicted from the caller and wraps to two lines on narrower devices and at larger font scales when squeezed into the text column (see the Deadline summary line entry in components.md). A trailing **set-progress chip** — a `surfaceContainerHigh`, fully-rounded, 38dp-tall pill holding a single pencil glyph, no chevron (a chevron there implied a dropdown menu the tap never opens — it always just opens the sheet; `DesktopTooltip`-wrapped, one `contentDescription`-carrying tap target) — opens the same Update-progress sheet the hero's filled pill does. Reach for this row anatomy for any future Reading-style secondary list; the section opener above it ("Also between your fingers") is the two-tier eyebrow ("N more in motion") + `headlineSmall` headline pattern (§3.2, deliberately stepped down from the redline spec's full `display` role, which read as oversized for a body-section opener), not the single-line `SectionLabel`.
